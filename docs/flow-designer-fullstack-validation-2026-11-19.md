# 网站开发 Flow 验证记录

## 用例与验收方法

Windows 桌面的设计助手曾把网站开发需求显示为“设计未完成：设计模型返回无效 JSON”。原失败只留下界面诊断，无法还原当时响应的具体写法。此次验证使用同一个已配置的模型连接，在独立便携数据目录中设计模板、导出 JSON、重新导入新模板，并在空工作区运行一个前后端分离的任务看板。

**最终结果（2026-11-20）**　用已配置的模型运行原七节点图，架构、前端、后端、初测、修订、复测、交付全部完成。保留既有网站后的这次运行耗时 40 分 16.485 秒，共 99 次真实模型请求。30 分钟观测点仍在修订岗。初测找到了零测试退出问题，修订与复测实际执行了 29 项用例。Windows、Linux 和真实 Chrome 对最终交付副本的独立结果见[端到端验收](#端到端验收)。

| 环节 | 通过条件 |
| --- | --- |
| 设计与导入 | 能生成可导入的模板，导出再导入后的配置一致，用户可自行选择工作区。 |
| Flow 执行 | 架构、前端、后端、测试、修订和复测都完成，节点间有真实交接。 |

| 发布 | Windows 和 Linux 回归通过，两个平台的可执行成品通过自己的离线自检。 |

### 设计结果

使用已配置的 `deepseek-v4.1-flash` 和 Windows 系统代理，设计请求一次成功，耗时 99.64 秒。供应商回报 3,733 个输入 token 和 6,835 个输出 token。生成图共有六个节点和六条边。架构设计后把契约交给前、后端，两者交接到同一测试节点，测试结果经过修订和复测。调度器按拓扑顺序执行，这里的反馈采用有限的修订轮次。该模板经产品接口导出、导入后配置一致，且未绑定工作区。

### 首轮执行与修复

首轮业务执行耗时 504.70 秒，发出 19 次模型请求。架构节点已交接。前端节点写入页面、样式和脚本，随后静态检查返回 44 项通过、1 项失败。该结果尚未送回模型时，估算的下一请求需要 16,784 个输入 token，超过 16,000 的原限额。前端进入检查点，后端及后续节点被阻断。

将同一会话复制到隔离目录，保留原有工具定义、当前输入和最新工具调用与回执，分别使用旧窗口和本地结构化历史组装下一次请求。最保守的辅助输入估算下，归档已交付的旧批次后只需 10,068 个 token，另有 2,000 个预留，最新自检结果仍完整。此对照没有向模型发请求。

设计器另有格式和取消回归，覆盖代码围栏、简短的模型说明、多份候选、截断、无效结构和受限的单次格式修正。Windows 使用产品默认的 WSL 解释器发现规则，并实际通过 Windows 到 Ubuntu 隔离执行器的探测。该环境仍需先按 Windows 指南安装。

### 长节点重复检查

第二次从空目录运行同一个六节点模板时，架构节点确实使用了结构化历史。停止前已归档 27 个批次，窗口为 9,819 / 16,000 token。它写入架构文档，随后反复读取文件，未交给实现节点。两次确认由于测试操作员未能在原 30 秒内响应而取消。为控制重复请求，测试在第 31 次请求时中止，有 30 次收到完整用量，第 31 次调用的用量未知。此轮只产出架构文档。

核对已配对的工具记录，发现进度提示会因取消或失败的命令清空读取计数。同一文件或命令的最新失败还会遮住早先的成功回执。修复后，模型能同时看到两类结果，达到节点验收条件即可交接。如有具体缺项，提示会指向对应的核查工作。读取权限、文件写入确认和命令限制继续生效。这次停止留下的测试实例在正式运行时再次启动时恢复为 interrupted，恢复过程没有调用模型或重放操作。验证驱动随后增加了单次确认通道和正常停止、等待排空的入口。

### 截图原句与原生界面

在 Windows 使用独立数据根启动 Qt 原生主窗口和运行时，通过输入框和发送按钮提交截图中的原句，要求先设计网站架构、分别实现前后端，再由 AI 测试并反馈。实际模型一次响应，耗时 74.47 秒。窗口结束等待，显示对话回复及含 7 个节点、7 条边的模板。使用原生菜单导出，再通过菜单重新导入，节点和连线数保持一致。本项使用 Qt 离屏显示，操作经过真实控件、实际模型连接及产品的模板存储。

该图依次覆盖架构、前端与后端分工、AI 测试、一次修订、复验及交付汇总。生成的说明曾把分支写为并行实现。调度器实际按拓扑顺序串行调度，本次也据此明确了设计器的分支说明。

### 七节点空工作区运行

从全新空目录运行原生界面导出的七节点图。架构在约 400 秒时完成，交接按配置的字段通过校验。前端产出 `static/index.html`、`static/style.css` 和 `static/app.js`。独立 Node 语法检查退出码为 0，HTML 有表单并引用两个同源资源。随后前端持续读取同一批文件，未交接。为控制重复开销，通过产品的取消入口停止并等待实际排空。

本轮持续 1,268.80 秒，发出 54 次请求，52 次成功、1 次超时、最后 1 次因正常停止中断。52 份供应商用量合计 542,256 个输入 token 和 29,368 个输出 token。14 次确认及时处理，1 次因操作员未能及时响应而过期。没有后端入口，未进行 HTTP 或完整浏览器验收。所列前端检查只证明对应静态产物。

在保留项目文件的情况下，对原前端会话追加了一次针对性交接请求。它仍继续读取文件，手动正常停止并排空后没有最终交接。此次耗时 126.64 秒，共 7 次请求，其中 6 次成功，最后 1 次被停止。因此单独重述任务和验证事实不足以作为本例的收尾办法。

### Windows 文件换行

检查实际产物时发现同一文件中混有 LF 和 CRLF。独立的 Windows 原生红测确认，写入工具会把传入的 LF 转成 CRLF，已经包含 CRLF 的文本会多出一个回车。全量更新的确认检查还会遗漏仅换行不同的变更。这会影响下个节点按字符翻页和精确匹配原文。修复后，写入保留传入文本的原始换行。Windows 文件工具专项 35 项通过、3 项按平台跳过，Linux 38 项通过。上述缺陷使用最终修复代码专项复验；模型读取文件的次数还受节点指令、模型行为和人工确认影响。

### 反复读取后的交接判断

对同一批文件反复读取时，单独增加一条文字提醒在真实会话中没有促成交接。修复改用当前节点自己的下一轮模型请求，请模型依据工具回执和岗位验收条件选择交接、继续具体工作或说明阻塞。该轮关闭工具。批准、文件操作、最终交接契约和运行预算仍由原路径执行。

通过隔离的会话与正式调度入口进行离线回归。覆盖页内重复、连续分页、只读既有产物、下游实际收到结构化结果、恢复工具、取消、超时、判断无法装进窗口、非法工具调用，以及只读权限拒绝写入。旧实现上的两项关键断言均失败。回归里的模型回复由用例控制，文件工具、调度与交接实际执行，真实模型表现单列记录。

### 从模板到可运行的网站

在独立数据目录中双击 Windows 单文件候选版（源码 `7a59c03`），通过实际可见的原生窗口输入截图原句。已配置的模型生成了 8 个节点、9 条边和 2 个节点自定义工具。通过「更多 → 导出」得到 26,784 字节 JSON，再从同一界面导入。新旧模板的 ID 不同，产品导出的配置逐项相同，均可独立选择项目。原生控件的离屏验证、实际可见 EXE 和早期产品接口分别生成了七、八、六节点图。

Windows 单文件候选版 `164e3f1` 另经真实可见的原生窗口复验。点击「更多 → 导出」，系统文件对话框默认进入便携数据根下的 `data` 目录，并预填 `flow-template.json`。直接保存得到 26,784 字节，与上次导出的原文件 SHA256 相同。通过「更多 → 导入」选择该文件后，新模板在画布展示八个节点和九条边。用产品的导出接口核对验证目录内三个不同 ID 的模板，三份配置逐项相同，均未绑定项目或工作区。这次仅操作既有测试模板。

在保留前端文件后，原七节点模板的一次新运行用时 1,727.98 秒。架构与前端完成并交接，后端写入了第一份 `app.py`。下一次请求连同必须回传的最新工具批次需要 17,433 个输入 token，含 2,000 个预留共需 19,433 个，超过当时的 16,000 上限。随后用 32,000 的测试进程输入窗口将真实交接交给剩余五个节点。后端完成了服务与自检。初测两次在 90 秒时限内未能生成完整的测试文件工具参数，这两次调用均未写入文件。补丁改为按照节点实际可用的创建和编辑工具提示分组写入，耗尽恢复次数时保留已经成功的回执。

独立验收在 Windows 和隔离 Linux 中分别启动同一版本的站点，两端各通过 48/48 项 HTTP 检查。使用临时数据文件检查了任务创建、更新、筛选、统计、删除、错误响应和重启后的数据。真实 Chrome 在 1440×900 和 390×844 两种视口下完成创建、切换状态、筛选、刷新与删除，均无横向溢出。此时还发现浏览器自动请求 `/favicon.ico` 返回 404。

保留以上文件，在原七节点模板中提出修复图标和完成网站测试的增量任务。运行后 1,022.95 秒进入前端，1,393.27 秒进入后端，1,681.45 秒进入初测。前端写入 SVG 并在页面中引用它。两种浏览器视口再次通过操作检查，五次实际图标请求均为 HTTP 200，正常操作期间没有网络失败、JavaScript 异常或 HTTP 错误。后端随后补上兼容入口，隔离 Linux 实测 `/static/favicon.svg` 与 `/favicon.ico` 均返回同一份 326 字节的图标，内容类型为 `image/svg+xml`。

### 模型断线和主机重启

原 1,800 秒观测点时，测试岗位仍在运行。到 1,985.42 秒，第 67 次模型交互在建立连接时中断，已保留 4,389 字节的测试框架和前三个岗位的完整交接。当时剩余三个岗位均被阻断。

恢复后的 Windows 运行时使用产品的「从中断节点继续」入口，同一实例、同一测试会话取得下一轮模型响应。恢复前后三个已完成节点的记录逐项一致。初测继续写入测试，使 `test_app.py` 达到 8,820 字节。主机随后重启。重启后独立复制该站点，在隔离 Linux 执行 `python3 -m unittest test_app`，实际发现并通过 15 项测试。此刻直接运行 `python3 test_app.py` 会静默退出，仍需补齐测试入口及 CRUD 与持久化用例。原实例保留了这些文件和模型交互，未取得交付节点完成回执。

### 在保留的工作区继续完成网站

主机重启后，用同一份七节点模板重新导入并创建项目，工作区指向先前生成的网站。模板文件的 SHA256 为 `523efc760dfac4a7141e84d99b5e79ce0387dbf1d9239092aca438b16bd75f4b`。新实例使用已配置的 `deepseek-v4.1-flash`、Windows 系统代理和本次运行的 32k 输入窗口。用户输入让测试岗位补齐可直接运行的测试入口、CRUD 与持久化用例，并把结果交给修订和复测岗位。普通会话默认输入窗口仍为 16k。

架构完成后，前端在第 285.17 秒开始，后端在第 513.91 秒开始，初测在第 818.24 秒开始。后端实际发现，`--data-file` 指向尚未创建的多级父目录时，首次写入会返回 HTTP 500。节点修改了生成项目的 `app.py`，用同一数据文件两次启动网站并核对记录，随后交接。独立验收在 Windows 和隔离 Linux 各通过 7 项检查，覆盖首次写入返回 201、数据文件实际创建、第二次启动仍能读回同一任务及两个图标入口。两端测试的后端文件 SHA256 相同，为 `9577904ee4db64a666e496b0972edc0fd1e574c37066ea2afe6c57bc2495ce01`。

初测将原脚本“直接运行退出 0、实际执行 0 项”及 CRUD 和重启持久化的覆盖缺口写入 `docs/test-report-1.md`。修订节点保留 15 项原测试，补了 14 项和可执行入口。修订岗实际执行 `python3 test_app.py` 得到 29 项通过（0.532 秒），复测岗独立重跑得到 29 项通过（0.805 秒），并写入 `docs/test-report-2.md`。交付岗输出 `docs/delivery-summary.md`，内含启动命令和自测说明。这次增量输入要求使用说明，模型将它放在交付文档内。
