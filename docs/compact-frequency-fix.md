# 上下文 Compact 频率与预算修复（2026-10-12）

## 行为与根因

旧实现可能在已经没有可压缩余量时仍启动摘要流程，也可能频繁调用监督评分和摘要模型。固定系统提示、工具 schema、当前输入及预算预留本身超过上限时，归档历史无法解决预算错误；而小批硬整理反复请求摘要模型，也会增加调用次数。

当前准备流程先测量固定成本。固定成本已超限时立即返回预算错误，不发布摘要或归档。达到硬预算（利用率 `>= 1`）时绕过软冷却、重复历史指纹和监督评分，直接规划可行窗口；预算规划同时计入工作摘要、归档引用、受保护的完整历史组和后续执行余量。若只缩短工作摘要或引用就足以满足预算，则不调用摘要模型，也不发布新归档。完整原始历史仍按原样保存在归档中，Compact 只调整模型窗口。

低于硬预算时，软 Compact 仍按 `CONTEXT_COMPACT_RATIO` 阈值、监督器判定、历史冷却和重复指纹规则执行。默认至少新增 4 个完整历史组才进入下一次软判定；把 `CONTEXT_COMPACT_MIN_NEW_GROUPS` 设为 0 可关闭该冷却。目标占用和软冷却设置见[结构化历史与上下文管理](context-management.md)。

硬预算下，满足小批条件时使用本地摘录并标为 `extractive_budget`，避免为小批整理再次请求摘要模型。任何预算规划仍保留完整工具请求与结果组；如果固定成本或最小归档开销仍无法容纳，返回预算错误，不提高输入上限、不拆分工具批次，也不丢弃原文。工作摘要和引用上限会作为当前归档视图的设置保存；之后增加预算不会自动扩大它们。完整归档内容仍可在 DEBUG 上下文归档页查看，历史检索也可查询已归档块。

## 合成负载测量

对同一 48 轮工程负载做 5 组配对测量，临时存储，摘要调用人为加入 1 ms 延迟。表中为配对结果中位数；这是 Compact 频率与本地准备开销的合成测量，不是回答质量或真实模型延迟评测。

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 准备耗时 | 0.2297 秒 | 0.1195 秒 |
| Compact 次数 | 20 | 10 |
| 摘要请求数 | 70 | 4 |
| 预算错误数 | 0 | 0 |

覆盖还包括成功的 provider 返回 2000 字摘要，以及已有归档在更紧预算下仅收窄工作摘要、未调用模型且未发布新归档。测试不评估摘要语义质量。旧人工会话记录在约 16 分钟内触发 48 次 Compact，均由硬预算触发；该记录没有轮数数据。合成结果不代表该会话会有相同的模型调用或延迟。

实现没有新增配置项。当前 `.env.example` 中已有 `CONTEXT_COMPACT_TARGET_RATIO` 和 `CONTEXT_COMPACT_MIN_NEW_GROUPS`，语义见[结构化历史与上下文管理](context-management.md)。

## 2026-10-14 大批硬预算整理修复

后续实测发现，硬预算下本地摘录的触发条件曾受 8000 字符分块门槛限制：当历史批次较大、已有硬预算回退标记，或摘要/工作摘要预算不足时，仍可能先请求付费摘要模型，再因预算失败回退。现在这些硬预算路径直接使用 `extractive_budget`，大批次也不会重复尝试摘要；正常软触发和可用的模型摘要流程保持原有行为。

请求和预算共用的工具 schema 会移除 JSON Schema 节点上的 `title` 注释，以减少固定上下文开销；工具名、描述、参数校验、默认值以及用户参数中名为 `title` 的字段均保留。此项不改变输入 token 上限，也没有新增配置项。

### 真实会话离线重放

使用一段真实会话的 188 条消息，按 65 个完整历史前缀做 3 组配对重放。每组使用临时存储和离线摘要替身；摘要等待固定 1 ms 后明确失败，不调用模型 API，也不执行原工具。修复前从 `/tmp/compact-baseline-1014` 加载基线源码快照，修复后使用当前工作树。主要结果如下：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 摘要尝试 | 74 | 0 |
| Compact 次数 | 20 | 18 |
| 归档块数 | 54 | 53 |
| 预算错误 / 超限请求 | 0 / 0 | 0 / 0 |
| 准备耗时中位数 | 651.4 毫秒 | 525.0 毫秒 |
| 工具 schema 大小 | 20874 字符 / 7869 估算 token | 18322 字符 / 7231 估算 token |

工具 schema 字符数减少 12.2%，估算 token 减少 8.1%。两侧原始消息的 SHA-256 均未变化，工具调用与结果配对校验通过。耗时只反映本机 CPU 和人为固定的 1 ms 延迟，不能代表真实模型时延或摘要质量。

原会话审计记录有 27 次 Compact 提交；56 个归档块中，35 个摘要标为 `extractive_fallback`（失败类型为 20 个 `ValueError`、15 个 `TimeoutError`），15 个标为 `model`、6 个标为 `extractive_budget`。这些是块摘要类型统计，不能推断原运行的摘要 API 调用次数，也不等同于上述重放次数。计划证据提交至 Compact 提交的间隔中位数为 20.012 秒，只是代理指标，不是精确的运行阶段耗时。

重放对比的是临时快照基线与当前工作树，不是 Git `HEAD`；基线快照仅在生成报告的环境中保留，其他机器没有该快照时不能复现相同的修复前比较。固定 runtime 由用户指南、初始任务执行策略、权限和计划协议组成，不含动态计划摘要、记忆或逐轮运行提示，因此结果不是完整原始执行的逐字复现。
