# Agent Flow 多用例验收（2026-10-28）

本轮把原生 GUI 的项目创建、Flow 编辑与执行功能接入 WebUI；保持 Core 的 DAG、项目身份、权限、确认及持久化实现。使用独立临时状态和项目，既有用户会话、工作区、凭据及服务不参与测试。README 按用户明确选择恢复并更新。

## 验证类型

- **离线回归**：真实 FastAPI、SessionStore、Core 工具及权限，模型使用明确受控回调。Node 测试执行实际前端状态逻辑与 DOM 替身，不等于浏览器或真实模型执行。
- **实际浏览器**：独立本机 Web 服务、真实 HTTP/SSE、DOM 输入、鼠标拖动及端口连接；服务仍使用受控模型，以确定性触发完成、失败和取消。
- **真实模型**：使用已有模型配置调用实际 provider，运行真实文件与命令工具；另做独立结果校验。未以受控回复代替这些请求。

## 浏览器与接口用例

| 用例 | 操作与观察 | 结果 |
| --- | --- | --- |
| W01 串行两节点 | 目录窗口选择中文项目路径；连续输入名称与指令；鼠标移动节点、拖端口连线；保存并运行 | 两节点完成，运行检查器保持选中，指令保存为非空 |
| W02 分支汇合 | 载入含负坐标和大坐标的三节点图，适配后全部可见；运行两起点汇合 | 坐标保持，三个节点完成，下游收到两份交接 |
| W03 主动取消 | 起点等待，运行中检查顶部和检查器项目选择锁定，再点击停止 | cancelled，下游 blocked；同项目可再运行 |
| W04 模型失败 | 起点受控异常，观察后续节点及运行详情 | failed，下游 blocked，不把失败当成功交接 |
| W05 服务中断与重开 | 页面保持打开，实际中断独立服务的运行节点并用同一状态重启 | epoch 更换，页面不刷新即可恢复；原 run 为 interrupted、ID 保持，模型活动数 0，没有自动重放 |
| W06 经典项目与草稿回切 | Agent/Flow 模式来回切换保留 readonly；创建经典项目；编辑 Flow 后切换另一 Flow 再返回 | 初始权限 readonly；未保存草稿保留，随后保存成功 |
| W07 目录选择与后台刷新交错 | A 打开目录窗口，另一客户端运行 B；实测 A 发生四次详情刷新后选择第二项目 | 新路径写入当前 A 草稿并保存，未被旧对象吞掉 |
| W08 会话跳转与删除 | 从节点运行详情打开真实会话；删除失败 Flow 时明确确认 | 会话正常打开；Flow 删除，节点会话与项目保留 |
| W09 窄屏 | 450 px 页面检查画布、检查器与页面尺寸 | 文档宽 450 px，无页面横向溢出，检查器可滚动访问 |

接口回归另覆盖 stale revision、URL/body ID 错配、显式删除同意、同项目争抢及异项目独立、跨源拒绝、已知密钥脱敏、SSE 不广播完整背景、模型 Flow/节点引用、经典设置/记忆与维护入口的预约保护，以及只读拒写与确认超时。边界拒绝均作为预期结果验证。

## 实际发现并修复的问题

| 编号 | 失败症状与原因 | 修复及验证 |
| --- | --- | --- |
| D01 Web 缺少 Flow | GUI 功能在 Web 没有入口，GET/POST `/api/flows` 返回 404 | 接入同一 FlowService、API 与画布；缺失接口 4 项失败回归转通过 |
| D02 排队状态不结束 | HTTP 操作 pending 时消费最终 SSE revision，却不读取详情 | 操作结束补读详情，pending/completed 交错回归转通过 |
| D03 重启后列表失效 | 重启的 revision 从 0 开始，被旧客户端版本永久拒绝 | 新增生命周期 epoch，拒绝同实例旧消息与旧实例迟到响应；回归及实际重启通过 |
| D04 长历史不能保存/重跑 | 把完整 run 和累计交接回传；11 节点各输出 50,000 字符时请求约 1.06 MiB，触发 413 | 只上传定义字段；实际 HTTP 请求约 2.2 KiB、PUT 和再次运行成功，原历史保留；请求容量限制保持 |
| D05 目录修改丢失 | 后台详情替换草稿对象，目录窗口确认仍写旧对象 | 按当前 Flow/节点 ID 定位，并检查打开/选择代次；Node 回归与 W07 真实交错通过 |
| D06 连续输入丢指令 | 名称 change 同步重建表单，下一项输入进入已脱离的控件；两次浏览器复现指令长度 0、保存 422 | 字段变化只更新相关文本和摘要，聚焦时保留草稿与表单；真实连续输入保存及 DOM 回归通过 |
| D07 项目/画布对等缺口 | 非法父目录路径被预览为有效；负坐标节点不可见；检查器 tab 被重绘重置 | 语法预览与 Core 对齐，使用缓存解析、动态边界/偏移和独立 tab 状态；纯函数及浏览器用例通过 |
| D08 经典初始权限缺口 | 原生创建支持权限，Web 拒绝该字段且控件只对 Flow 显示 | 共用公开策略选项，沿用桌面创建后设置路径；只读实际拒写，默认和非法字段回归通过 |

D02、D03、D04 有失败回归后修复；D05 由独立 Node harness 先复现，再补回归并做 W07。D06 先有实际浏览器失败证据，再补受控 DOM 回归。路径/坐标部分行为覆盖在修复后加入，不冒称全部都有独立修前红测。

## 真实模型用例

| 用例 | 环境与任务 | 实际结果 |
| --- | --- | --- |
| R1 串行修改与验证 | sandbox、full_access；分析、实现、验证三节点，修改整数金额求和函数 | completed；16 次模型调用，77.925 秒；父任务独立验证空列表、非负求和、负数/非整数拒绝及输入不变 |
| R2 初次分支汇合 | local、full_access；两起点读取标记，下游汇合 | failed；12 次模型调用，43.121 秒。与 R1 共用的验收脚本 28 次请求额度耗尽，join 被阻断，**不计为成功** |
| R3 独立只读分支汇合 | local、readonly；两起点读不同文件，下游只返回两个上游标记 | completed；5 次模型调用，15.450 秒；独立核对两份输入和最终输出，项目文件清单与 SHA-256 保持 |

共 33 次真实模型调用、33 次底层请求尝试，token 来源均为 provider。实际收到 32 条工具结果，包含 7 次 run_command、1 次会话委派与 1 次等待子任务；这些是执行记录，不代表每条工具都成功。脱敏汇总保存在本轮摘要。R2 的额度仅属于临时验收驱动，没有添加生产限制。R2 已出现目标文件，但运行未正常结束，因此没有用“文件存在”冒充成功；R3 是使用独立额度的只读场景，没有覆写 R2 失败记录。未配置可靠单价时不报告费用为零，也不据此推算真实能力或吞吐。
