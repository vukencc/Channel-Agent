# 工具设计与简化

优化目标是减少重复入口和不必要的模型往返，保留不同操作所需的校验、权限、审计与结果语义。工具注册表、模型实际看到的目录、可信界面服务分别承担不同职责。

## 审查结论与实施

| 原设计 | 当前处理 | 保留的能力 |
| --- | --- | --- |
| `create_session` 与 `delegate` 都启动子 Agent | 模型默认只看到 `create_session`，迁入延迟启动参数 | 独立上下文、共享项目、工具能力继承、轮次与延迟策略 |
| `task_status` 与等待接口重叠 | 使用 `wait_agent_task(timeout_seconds=0)` 立即查询 | 归属校验、结果、真实状态及排空状态 |
| 后台命令分别查询状态与日志 | `inspect_command_job` 一次返回状态与有界日志尾部 | 启动、停止仍为独立操作；检查返回完整 JSON 与截断信息 |
| 新建用户会话调用模型工具注册表 | `open_session` 直接执行可信 Core 服务 | 标题校验、工作区与环境授权、持久化和审计 |
| 默认可创建孩子，单独取消却依赖旧功能开关 | 常驻提供 `cancel_agent_task` | 仅取消自己拥有的子任务，遵循原取消和排空流程 |
| 用户手动挑选每个会话的工具 | 移除桌面/Web/CLI 入口，HTTP 设置拒绝 `tool_names` | 框架按有效能力上限生成目录；旧限制不被扩大 |

旧工具名称保留为兼容调用入口。只有替代接口也被当前策略允许时才从模型目录隐藏旧接口；旧会话若仅获准使用旧名称，仍保留其能力。目录顺序稳定，请求构造与上下文预算使用相同的实际 schema。

## 哪些行为交给框架

新建用户会话属于可信应用生命周期，由框架直接执行，不需要模型选择工具或往返一次工具协议。权限判定、参数验证、超时、取消、工作区身份检查、审计和 tool-call/result 配对继续由框架统一处理。

信箱投递、计划摘要和执行证据注入在此前已由框架负责，本轮没有把这些既有行为当成新的优化成果。手动信箱读取保留历史分页和追赶积压的用途。

## 保留独立工具的理由

- 文件创建、追加、唯一锚点编辑、覆盖和删除各有不同的安全与原子性语义，保留专用工具。
- 计划创建、查询、修订、步骤更新、执行绑定和归档分别改变不同状态；框架不能因命令退出 0 就替模型宣布任务通过验收。
- 历史搜索可选择 BM25 或混合检索，按 ID 读取提供明确分页和归属边界，继续保留。
- 前台命令、受管后台命令与依赖安装各有不同的生命周期和确认要求，继续分开。
- 环境探测仍执行真实检查，不用“找到可执行文件”替代“实际可以运行”的证据。没有自动执行依赖安装或安装脚本。

`MODEL_TOOL_NAMES` 是部署策略的能力上限，模型对子 Agent 的工具收窄也是内部约束；两者与已移除的用户界面工具选择不同。权限模式和 Linux 工作区选择继续提供给用户。

## 验证

回归覆盖兼容名称与策略边界、模型请求和预算目录一致、延迟启动、默认子任务取消、后台命令归属/日志/JSON 上限、无工具注册项时的框架新建会话，以及用户工具选择入口的拒绝行为。目录大小仅作为 schema 成本测量，不代表模型质量或真实计费。

## 目录成本测量

在全部可选 Core 工具均注册的受控配置中，旧设计最多 37 个入口；新增后台命令联合检查后，兼容注册表为 38 个，实际发送给模型的自动目录为 34 个。兼容名称仍可执行，不等于删除旧能力。默认仅启用部分功能的实际数量会不同；常驻取消入口补齐了原本缺失的能力。

以当前同一进程、同一会话约束及相同标题剔除规则序列化紧凑 JSON，兼容目录为 24,103 字符 / 33,351 UTF-8 字节，实际目录为 22,713 字符 / 31,693 字节；减少 1,390 字符（5.77%）/ 1,658 字节（4.97%）。这是当前兼容目录与实际目录的对比，不是旧版本真实请求、模型 token 账单或速度提升测量。
