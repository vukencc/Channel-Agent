# 设计助手连接与对话体验验证（2026-11-12）

> 文档类型：本轮验证记录 · [Flow 指南](agent-flow.md) · [Windows 连接](windows.md#模型连接与代理) · [文档导航](README.md)

## 问题与方案

用户报告模型配置正确，但设计助手提示连接失败；同时历史、输入和模型设置混在狭窄侧栏中。首次只读排查确认设计助手与正常会话使用同一模型连接，没有独立的错误端点。模型管理保存仅验证字段及安全持久化，不测试真实连通性。

本轮隔离实测发现用户持久 `ALL_PROXY` 指向拒绝连接的本地代理；已启用的 Windows 固定系统代理则是不同且可用的目标。修复提供每个模型连接的显式代理来源选择，默认仍继承环境；选择 `windows_system` 后使用 Windows 手动系统代理，保留系统排除、`NO_PROXY` 和 TLS/证书环境。不会修改用户或系统环境、自动迁移既有模型、静默切换代理、直连或降低推理强度。非 Windows、仅 PAC、缺失或无效的固定代理会报错。该字段不进入模型采样参数或便携 Flow 模板。

设计助手原先丢弃所有模型事件，将首段响应前失败和生成中断显示成同一连接错误。现仅保留内部安全阶段，分别提示且不导入不完整模板；底层异常、模板片段、推理及代理地址不回显。锁定 SDK 已会包装 HTTPX2 流异常，本轮修正的是底层传输类别被记录为 `unknown` 的诊断缺口，没有将它描述成已复现的服务商错误分类问题。

桌面与 Web 将历史按用户、助手、错误区分，多行输入、底部模型/推理与主操作组成独立输入区。生成时活动指示与停止按钮显示，失败后才显示重试；重试保留新草稿、不重复追加失败用户轮次。清空会取消当前设计，隐藏保留草稿；阅读旧消息不会强制滚到底部。仅调整设计助手，不重新设计 Flow 画布。

## 受控工程与界面验证

受控 HTTPX/SSE 使用实际 OpenAI SDK 和 Core `call_model`，覆盖传统 HTTPX 与锁定 SDK 的 HTTPX2 两个后端；首段前保留重试，首帧后不重放。覆盖正文/元数据首帧、取消、超时、三档权限、选中 profile 与 `xhigh` 保持，以及无密钥/异常正文回显。初始阶段归因回归 3 项失败；HTTPX2 类别新增断言有 9 项失败，分别修复后通过。新增异常脱敏用例也先失败后修复为固定提示。

代理专项使用本地受控代理与 TLS 服务，验证坏环境代理不影响显式系统模式、默认失败不转系统、按协议选择、IPv4/IPv6/域名/端口和系统排除、证书文件与证书目录信任、未信任证书拒绝、创建期间取消和关闭失败后的其它 transport 排空。审查发现 `NO_PROXY=::1/128` 构造无效并阻断普通域名的 P2，先复现后按 SDK 规则修复。旧注册表不自动重写、更新省略字段保持、不可变快照、FastAPI 实际 CRUD、Qt 点击保存及模板不携带网络连接均有覆盖。

Qt 截图使用应用实际主题与字体配置，但为离屏检查。Web 使用独立 `create_app` 的实际本机 HTTP 服务和受控设计回调，检查 1440px/416px、发送/停止/重试显隐、旧历史滚动位置、关闭重开保留草稿、失败重试及清空取消后的迟到结果不导入。未把受控回调称为真实模型业务运行。窄屏收口过程中复现控件重叠，补容器高度和几何回归；取消后立即再发可能在排空期间收到受控 409，排空后可重试。

## 最终修复与平台结果

导入恢复审查发现：模型已完成设计但保存失败时，原重试会再次请求模型并重复追加助手历史。现在两端保留生成结果，只重试导入；稳定请求 ID 对应稳定模板文件，并核验磁盘身份。相同内容跨服务重载仍返回同一记录，内容已改或发布状态不确定时拒绝重建；不带请求 ID 的普通导入仍建立独立副本。真实临时文件、API 和桌面桥接 **19 项通过**，包含写入前/后失败、审计失败、外部变更、取消与切换后令牌失效。Qt 还修复了 Unicode 码点与 UTF-16 游标偏移混用；16,001 个 emoji 截断后保留 16,000 个，而非错误地只剩 8,000 个。

Linux 首次全量未把 Linux/nvm Node 加入执行 PATH，38 项 Node 用例因运行器找不到 `node` 失败，其余 2250 passed、56 skipped、5 deselected（302.22 秒）；没有据此修改产品或跳过用例。加入正确 PATH 后完整复跑 **2325 passed、42 skipped、5 deselected（228.49 秒）**，后续最终输入区/恢复补丁再经专项及 CI 验证。`499421c` 的 [CI 43200240173](https://github.com/vukencc/Channel-Agent/actions/runs/43200240173) 双端成功：Linux **2321 passed、47 skipped、5 deselected（163.42 秒）**；Windows **789 passed、47 skipped（97.52 秒）**，真实隔离探针通过。

本机 Windows 默认 GBK 新增专项首轮 **2 failed、90 passed（60.22 秒）**。一项为标题栏最小宽度使请求的 230px 被提升到 250px，现允许标题收缩并保留无障碍名称，检验实际宽度、容器边界及控件不相交；另一项为测试先设置 `NO_PROXY` 再删除小写变量，在 Windows 大小写不敏感环境中误删刚设置的值，已只修正 fixture 顺序，未改生产排除规则或断言。修复后 **92 passed（38.99 秒）**。Windows 原生离屏截图使用应用主题与字体，实际宽度为 400/400px、230/230px，控件未重叠；证据在本地 `D:\AI\AgentSrcCode\ChannelAgent\.cache\reports\designer-native-qt-13cc3c18af50407faf81517afb0dfe51\`。

## 新代理实际请求与复杂设计限制
