## 产品修复与配置修正

1. **设计助手自定义模型缺少路由标识。** 真实请求返回 `MissingSessionID`。runtime与fallback客户端现在有独立默认会话标识，真实节点仍用自身会话ID覆盖；SDK HTTP回归先失败后修复，实际模型复验成功。
2. **Flow失败提示过于笼统。** 检查点按受控 `stop_reason` 显示连接、上下文或预算原因，未知原因保留通用提示，不回显服务商正文或模型消息。
3. **上下文指导推荐未启用的工具。** 根据当轮schema分别说明历史摘要、原文、文件和RAG能力，摘要截短通知也不再错误承诺原文可检索。
4. **未交付的最新工具批次被归档。** 无 `history_read` 时，尾部完整批次进入固定成本、规划和最终窗口，旧索引已覆盖时从journal恢复，不重复归档。装不下则在摘要或发布前预算检查点，保留配对，不增加预算。此保护由受控回归和只读复核验证；第五轮的大窗口运行不能冒称真实小窗口负向复验。
5. **设计输出截断被误报为连接配置错误。** `ModelResponseError` 给出精简模板或调整输出配置的安全指引。一次真实8192-token截断未创建空模板；随后精简提示并选低推理生成成功，没有提高输出上限。

测试模型连接起初未填 `context_tokens`，因此使用未知窗口的16k保守预算。实际provider `/models` 给出三个模型容量均为1M；最终新连接显式声明100k，与用户原全局容量一致，输出仍8192。旧连接和失败证据保留。这是准确补齐容量元数据，不是根据名称猜容量或修改全局预算。

另有工具配置缺口：大文件的 `update_file` 全文覆盖保护正常拦截，自检时缺少 `edit_file` 导致无法局部修订。通过真实UI显式选择局部编辑工具后，Agent执行真实 `edit_file`；没有删除保护、换工具绕过或人工修改业务JSON。模板的批量规则冲突、办理完整性和事实保真规则也通过独立副本明确人工编辑，保留修改前后哈希，不称它们是模型原样生成。
