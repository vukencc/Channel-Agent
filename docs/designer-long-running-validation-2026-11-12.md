# 设计助手长请求验证（2026-11-12）

> 文档类型：本轮验证记录 · [Flow 指南](agent-flow.md) · [连接与布局历史记录](designer-chat-validation-2026-11-12.md) · [文档导航](README.md)

## 目标和实现

用户要求取消设计助手固定 90 秒总时限，保留停止和取消；使用原五节点、四动态工具客服用例与 `xhigh` 验证完整生成及导入，不降推理强度或简化任务。

原实现有三处总时限：设计入口、模型调用整体、连接阶段按端点分摊。现在通过请求局部 `ContextVar` 明确将设计请求总时限设为 `None`，同时解除这三处限制。退出后恢复原作用域，并发普通 Agent 仍受原 `MODEL_CALL_TIMEOUT` 限制。没有修改全局默认值、模型采样参数、用户代理或模型配置。

`SESSION_TIMEOUT` 仍约束 SDK 网络连接及读取空闲，首帧前仍按原 `MAX_RETRIES` 重试，首帧后不重放。停止、清空、预算、字符上限、流完整结束校验和原子导入保持。设计过程及导入不执行生成代码，不绑定项目或工作区。此前 90 秒失败仍作为历史证据保留。

## 用例与证据边界

真实模型用例从上一轮脚本中 AST 提取原始 `PROMPT`，逐字校验 UTF-8 SHA256：`9dd9fd9bd02211f562941b30f43f8c635a448950f598462cc676332656755f69`，588 字符。模型仍是已保存的 `测试DS` / `deepseek-v4.1-flash`，设计请求固定 `xhigh`，显式 `windows_system` 连接；原 `ALL_PROXY`、`NO_PROXY` 和用户保存配置不改。凭据只在内存中读取，隔离状态不持久化密钥。

要求严格为五节点、四边：分类→技术初诊→模拟运维，以及分类→RAG 服务→人工接单。分类保留 ID、垃圾不回复、技术只初诊和运维交接、服务查询 `support` 知识库、无依据交人工；箭头不被宣称为条件路由。四个真实动态工具为 `read_feedback`、`send_ai_reply`、`submit_human_ticket`、`submit_ops_ticket`，仅标准库、项目内相对 I/O、保留原 ID、按 ID 幂等，失败报错且不声称对外送达。节点继承模型，使用默认文本交接。

验收顺序为：真实 `design_flow` →完整 schema 校验→`FlowService.import_template`→JSON 导出→服务重载→相同请求 ID 重复导入及定义比较。另阅读生成的节点提示和代码做静态语义检查；静态检查不等于执行业务或验证生成工具安全性。本轮不运行节点、不调用工具、不创建用户项目。

## 先失败后修复与受控验证

实际 Chromium 通过完整 `create_app`、真实 `llm.call_model` 和受控流，在 0.05 秒总时限配置下等待流启动后 0.7 秒，仍显示忙碌；分别停止与清空，均触发后端取消。受控流故意吞取消后返回迟到的有效模板，浏览器没有导入请求，API 中零 Flow；清空后历史为空。Qt 使用真实 `RuntimeBridge` 和设计助手离屏运行受控模型回调，同样验证超过总时限、取消传递、迟到结果不导入、命令队列和工作线程排空。Qt 首次探针未等待回调启动，观察无效，未计作通过；后续明确等待启动与排空。这些是受控验证，没有称为真实模型执行或实际等待 90 秒。

## 真实请求与最终结果

干净源码 `cd581879538652eac3724a3d3b77a8989d072479` 的 Native 首轮实际请求在 **164.497 秒**结束；Core 指标为 164.453 秒，首帧 5.344 秒、1 次请求，持续收到 **48,001 推理字符、0 正文、0 工具参数**，因原 `MODEL_OUTPUT_CHARS=48000` 合计上限抛出 `ModelResponseError`。没有再遇到 90 秒截断，但没有生成模板，导入及往返尚未通过，未盲目重试。输入/输出 token 为框架估计（3655/14276），不作为供应商账单用量或吞吐提升依据。

## 用户确认独立有界预算后的续验
