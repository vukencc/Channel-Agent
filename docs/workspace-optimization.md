# 工作区与上下文优化

本轮优化让长会话保留可用的项目进度，同时降低重复历史占用，并在 WebUI 中集中呈现任务与运行状态。

## 上下文整理

默认 `CONTEXT_COMPACT_RATIO` 从 `0.8` 调整为 `0.9`。压缩判断按模型输入、工具 schema 和用户/搜索预留共同计算字符与 token 利用率，取较高者；低于阈值时不会调用监督器检查，也不会压缩。本机 `.env` 仅将匹配旧默认值的该项同步为 `0.9`；其他配置与凭据保持原样。自定义阈值不自动覆盖。重启进程后生效。

常规上下文准备会缩短较早的大型文件读取结果和重复文件写入载荷，保留工具调用与结果配对。较早文件页需要时可再次使用 `read_file` 的 `offset` 或 `search`；完整对话记录仍留在会话历史中。结构化历史压缩时，每个归档块单独摘要；Session 摘要合并旧摘要与本批有界块摘要，不重复输入同一批原始历史。原始 journal 与归档原文不改写，仍可通过历史搜索定位摘要并按需读取原文。总结超时或失败会留下明确标记的本地摘录 fallback，不把失败状态记为成功。

## 执行进度提示

当本轮至少连续完成 6 次读取/搜索，或对相同参数与相同结果重复读取/搜索至少 3 次，系统会向执行模型附加进度提示。提示依据本轮真实配对的已执行工具结果，并包含最近最多 6 条真实工程工具结果，帮助执行模型回看已有产物、当前目标和下一项可验证修改或测试。

提示属于建议，不阻止工具调用、不构成权限检查，也不替代实际工具返回。它不会把工具成功直接解释为任务完成；模型仍须核对验收结果。该机制不创建独立任务计划，也不自动启动额外 Agent。

## WebUI 工作区

本机 WebUI 提供可拖动的三栏会话工作区。左栏展示会话，中栏用于对话，右栏上方展示任务分布、计划进度及 Agent/工具/任务监控，下方展示 Agent 当前状态；右栏两部分之间可调整高度。状态面板显示当前阶段并带动态 Agent 动画，底部显示会话、权限与模型状态。布局尺寸写入当前浏览器的 `localStorage`，模型凭据不保存在浏览器存储中。上下文状态可查看用量、预算、归档数量、监督器检查状态和摘要是否降级。

WebUI 的模型管理可保存 OpenAI-compatible 服务地址、模型 ID、参数和可选 API key。凭据保存在当前 `AGENT_STATE_DIR` 下的 `.runtime-models.json` 私有注册表；POSIX 环境要求文件为当前用户私有权限，保存通过临时文件和原子替换完成。会话只持久化非敏感的运行时模型 ID。密钥不会被 API 返回，也不会写入会话导出、浏览器存储或审计记录。新建模型的空密钥表示无密钥；不会回退到 `.env` 的 `OPENCODE_API_KEY`。编辑相同服务地址时密钥留空保留原密钥；更换服务地址必须重新输入对应密钥，防止凭据跨服务泄漏。

运行时服务 URL 仅接受无用户名、密码、查询和片段的 HTTP(S) URL。环境中的内置模型预设为只读；修改或删除模型前，所有引用该模型的会话与工具都必须空闲，删除前还需先将引用它的会话切换到其他模型。运行时模型选择只用于主执行器，不改写 `AUX_MODEL`、`CONTEXT_SUMMARY_BACKGROUND` 或 `MEMORY_AUTO_EXTRACT` 等环境配置路由；监督器仍由 `.env.supervisor` 独立配置。运行时模型请求使用注册表中的端点和凭据，不套用全局 `MODEL_FALLBACKS`、采样参数或 thinking/reasoning 设置，避免失败后意外切换到其他服务。

监督器仍是独立的可选配置，使用 `.env.supervisor` 与 `SUPERVISOR_*` 凭据，不继承主模型凭据、工具集或权限。它仅为压缩评分和摘要提供建议，无权改变任务、计划或执行操作；关闭结构化上下文时不会发送监督器请求。监督器样例中的启用选项不改变运行时代码的关闭默认值。详见[结构化历史与上下文管理](context-management.md)。

## 基准记录

固定合成轨迹为 36 次上下文准备，每组运行 3 次，摘要替身零延迟，不调用真实 LLM。优化前基线阈值为 `0.8`，最终默认为 `0.9`；两者历史输入相同。JSON 写入 `/tmp/context-progress-before-root.json`、`/tmp/context-progress-after-default-final.json`。

| 指标 | 优化前 | 最终实现 |
| --- | ---: | ---: |
| Compact 次数 | 8 | 5 |
| 摘要请求 | 44（块 26、会话 18） | 30（块 25、会话 5） |
| 摘要累计输入字符 | 167664 | 76987 |
| 本地准备总耗时中位数 | 0.0287516 秒 | 0.0382178 秒 |

新增边界估算使本地准备略有增加，不能宣称端到端提速。收益为压缩频率和模型输入工作量下降。相同 `0.8` 阈值的初步实现也测得 34 次摘要、86878 字符，见 `/tmp/context-progress-after-root.json`；该文件不是最终默认值的结果。

复现命令：`uv run python scripts/benchmark_context_progress.py --compact-ratio .9 --output /tmp/context-progress-recheck.json`。测试输入是明确标识的合成轨迹，摘要替身不能用于评价摘要语义质量。

## 实际工程追踪与修复

先前真实任务快照累计监督请求 447.442 秒、恢复轮主模型请求 55.456 秒，75 次工具调用中有 57 次 `read_file`。这里的“重复读取”计数包含不同页、不同文件，不能当作全部同参重复。此次固定 WorkBoard 工程任务在全新 `/tmp/agent-project-validation-optimized-20261007` 中运行真实模型，随后恢复一次。恢复轮再次出现连续读取与 `interrupted → in_progress` 被拒绝的问题；这次失败直接促成计划恢复修复。

| 核心问题 | 修复与验证 |
| --- | --- |
| 低占用仍按方差触发监督/Compact | 统一高占用门槛，低占用零监督请求；监督方差不能越过门槛。 |
| 多页原文反复进入会话摘要 | 原文逐块摘要后，只合并块摘要和旧 Session 总结；每批一次 Session 合并流程。 |
| 摘要/新引用使最终窗口反而溢出 | 估算新 manifest、保留工具完整组、JSON 转义与 token 上界；不可显示摘要控制字符视为失败并明确降级，原始历史不改写。 |
| 恢复计划只允许先回 pending，模型反复调用非法迁移 | 显式支持 interrupted → in_progress，继续校验版本、依赖、关联执行排空与单前台步骤，并审计。禁止自动重放或完成。 |
| 同一模型响应里读计划后再读取文件使版本过期 | 证据追加保留结构 revision；状态/结构写入仍严格 CAS，原子保存、审计与真实配对不变，Web 签名包含证据变动。 |
| Compact 后缺少文件进度、分页读取挤掉工程证据 | 注入真实配对写入/命令的有界收据及下一步建议；小预算仍保留最新工程证据 ID 和目标步骤。 |
| 持续读取/搜索不进入实现与验证 | 连续 6 次已执行读取或 3 次同参同结果读取提供进度提醒；写入/执行/步骤推进重置，拒绝、失败与缓存结果不充作进展。 |
| 只有工具历史的页面显示新会话欢迎占位 | 按真实历史数量与分页信息判定空会话；取消状态不误显示“准备就绪”。 |
| 新服务继承旧密钥/提供商参数、本地预算错误被遮蔽 | 服务地址变化须重填密钥；运行时参数与全局 provider 配置隔离，保留 BudgetExceeded 的 checkpoint 类型。 |

工程实验生成 4 个包文件，未建立自有测试目录，外部 32 项验收因存储外键错误均报错（退出 1），计划仍未完成。后续恢复轮用于诊断，修改了监督参数与提示词，不能与初轮做受控速度比较。随后将证据追加与结构版本分离：仍在同一锁下核验真实配对、原子保存并审计，仅步骤/DAG/归档等状态变更推进 revision；Web 签名包含近期证据，及时刷新。该修复以真实 `manager.submit` 失败回归转绿验证，不把旧版本证据追加失败忽略掉。最终修复由失败回归测试验证，未再次声称完整 WorkBoard 已通过。真实模型能否持续推进、长摘要质量仍需后续真实任务观察。

## 配置与数据边界

没有新增环境变量、模型下载或依赖。`CONTEXT_COMPACT_RATIO` 默认 `0.9`；结构化上下文与计划开关默认保持原状。新增运行时模型注册表为用户主动配置的功能，不自动创建连接；API key 输入仅持久化于私有状态文件，状态目录不可处于工具工作区或知识库可读根之内。监督器仍使用自己的环境配置。

测试与实验只写隔离临时目录。本次优化与验证没有清理、删除真实用户会话、缓存、日志或知识库。保留原有工作树改动，未提交或推送。本机最终回归与界面验证记录见下一节。

## 真实监督边界复验

执行 `SUPERVISOR_THINKING_MODE=disabled SUPERVISOR_TIMEOUT=30 uv run python scripts/context_validation.py`，真实调用监督 API，执行 Agent 不运行。高占用场景用明确标记的合成填充将输入校准至约 92%，预留置零仅用于边界实验，不改运行默认。输出 `/tmp/agent-project-validation-context-a6exr274/results.json`。

| 输入场景 | 初始占用 | 监督评分请求 | 归档 | 总耗时 |

| 低占用相关/无关混合 | 0.67% | 0 | 0 | 0.001 秒 |
| 高占用相关需求 | 约 92% | 1，方差 0 | 1 | 16.244 秒 |

## 最终实现后的恢复诊断

从同一个隔离工程目录恢复并发送明确的恢复/核验要求。真实调用成功将存储步骤恢复为 `in_progress`，随后完成两次 `run_command` 工具执行，包括存储 smoke test；工具执行成功不表示命令中的项目测试通过。该轮 14 次工具调用含 2 次版本冲突，进一步定位为同一模型响应中 `plan_get` 后的普通读取推进计划版本；主模型累计 35.287 秒、监督累计 93.438 秒，150 秒实验上限取消后计划再次标为 interrupted，仍未完成整体验收。改变了恢复提示词且复用历史，不能作为与初轮的速度对照。状态快照分别保留于 `observation-before-final-resume.json` 和 `observation-final-resume.json`。
