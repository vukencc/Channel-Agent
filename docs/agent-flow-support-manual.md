# 售后工单管理台：四 Agent 手动体验用例

> 文档类型：当前使用指南 · [文档导航](README.md) · [快速上手](getting-started.md)

本用例用于亲自体验 Agent Flow：让四个 Agent 按各自职责，在一个新项目中逐步交付可运行的售后工单管理台。这里提供配置和操作计划，后面的预期行为不是测试结果。保存模板不会创建项目、绑定工作区或运行 Flow；项目选择、运行和测试由用户自行操作。已有该模板时，可直接从下文第 5 步开始。

## 场景与分工

小型软件服务团队目前从聊天记录中跟进客户问题，容易遗漏。目标是生成本机运行的中文管理台，支持创建工单、查看详情、修改状态、组合筛选、关键词搜索、统计及 SQLite 持久化。

技术栈为 Python 标准库、SQLite 与原生 HTML/CSS/JavaScript，无需下载第三方依赖。它是本机单用户原型，不包含登录、附件、邮件或公网部署。

```text
需求与接口设计 → 后端与数据持久化 → 前端与业务交互 → 交付与手动操作说明
```

| 节点 | 读取 | 负责产出 |
| --- | --- | --- |
| 01 需求与接口设计 | 共同背景、当前项目 | SPEC.md：业务、字段、接口和页面流程 |
| 02 后端与数据持久化 | 上游交接、SPEC.md | app.py：HTTP 接口、SQLite 与静态文件服务 |
| 03 前端与业务交互 | 上游交接、SPEC.md、后端接口 | static/index.html、static/style.css、static/app.js |
| 04 交付与手动操作说明 | 上游交接、规格与实现 | README.md：启动、数据位置、手动步骤及未验证事项 |

四个节点共享项目文件，但各有独立会话。节点正常结束后的最终正文自动成为下游交接，不需要填写交接文件。提示词明确要求只做当前阶段、不要另行委派，所有节点均不运行测试或启动服务。职责提示仍取决于模型遵循程度，手动体验时可查看实际文件和调用记录。

## 配置文件

下述 `schema_version` 配方供手工配置或本页的 Web API 步骤读取，不是 `format: "agent-flow"` 的便携模板，不能直接作为画布的 JSON 文件导入。可先完成本页配置，再从画布导出便携模板。

完整背景、四段节点指令、位置及三条连线都在 [customer_support_flow.json](../src/agent_test/scripts/cases/customer_support_flow.json)。

这是可复用的用例配方，带有 `schema_version`、`case_id` 等说明字段，不能直接覆盖 `.agent/flows` 下的内部记录。它没有工作区、运行记录或预设模型；执行环境、权限和模型为 `null`，不会替用户选择或提高权限。

## 在 GUI 或 WebUI 中手工配置

1. 从左栏创建独立 Flow 模板，命名为“小团队售后工单管理台·手动体验”。此时不选择项目目录。
2. 打开 Flow 检查器的“可选补充背景”，将 JSON 中 `handoff` 的完整文本填入“项目背景（可选）”。使用 JSON 查看器复制解析后的多行文本；不要把外层引号和字面 `\n` 当正文。
3. 添加四个 AgentCore。按 JSON 中 `nodes` 顺序，分别填写 `title` 为名称、`prompt` 为节点指令。节点背景与已有交接文件留空。
4. 从前一节点的输出端口拖到后一节点的输入端口，按上述顺序连成一条链，不连回起点。保存模板。
5. 在应用源码目录之外手动新建一个专用空目录，例如 `/home/你的用户名/projects/support-desk-manual`。不要选择本应用源码、家目录根或存放重要现有文件的目录。
6. 新建 Flow 项目，显式导入刚保存的模板，用可视化选择器选择该空目录。模板与项目副本是独立的；项目背景可留空，避免重复粘贴共同背景。
7. 在项目设置中选择你要体验的模型、执行环境与权限。该场景不要求完全访问；默认“智能申请”会在需要时请你确认，只读权限无法完成代码生成。Linux 本机与隔离沙箱的具体边界见 [Flow 指南](agent-flow.md)及[沙箱说明](sandbox.md)。
8. 检查项目路径和四个节点指令后，由你点击“运行”。运行过程中按需响应权限确认。

如果应用进程早于上一轮 Core 修改启动，请先自行正常关闭并重启应用，使其载入当前代码。无需重建环境或清理用户数据。

## 可选：通过已有 WebAPI 保存模板

如果想省去逐段复制，可在已启动的本机 WebUI 服务上，自己执行下面的导入操作，再回到界面创建项目。原生 GUI 用户可以直接使用上一节，不需要启动 Web 服务。

在 **WSL / Linux 仓库根目录的终端**执行。`base` 改成实际 WebUI 地址，默认端口为 8765。这段操作只新建并保存模板，不创建项目、不选择工作区、不调用运行接口；本说明交付时未执行这些请求。每次执行都会创建一个新模板。

```bash
.venv/bin/python -B - <<'PY'
import json
from pathlib import Path
from urllib.request import ProxyHandler, Request, build_opener

base = "http://127.0.0.1:8765"
case = json.loads(Path(
    "src/agent_test/scripts/cases/customer_support_flow.json"
).read_text(encoding="utf-8"))
opener = build_opener(ProxyHandler({}))  # 仅此次本机请求不经过系统代理。

def send(method, path, value):
    request = Request(
        base + path,
        data=json.dumps(value, ensure_ascii=False).encode("utf-8"),
        headers={"Content-Type": "application/json"},
        method=method,
    )
    with opener.open(request, timeout=15) as response:
        return json.load(response)

template = send("POST", "/api/flows", {
    key: case[key] for key in (
        "title", "handoff", "execution_environment",
        "permission_policy", "model_profile",
    )
})
print("已创建模板 ID：", template["id"], flush=True)
template.update(nodes=case["nodes"], edges=case["edges"])
saved = send("PUT", "/api/flows/" + template["id"], template)
print("已保存：", saved["title"], "；4 个节点、3 条连线；未运行。")
PY
```

导入完成后刷新 WebUI，在 Flow 模板列表选择它。再按上一节第 5～8 步创建项目和手动运行。导入操作不会直接写应用状态文件，也不会调整服务配置；若创建成功而保存失败，会留下打印 ID 对应的空模板，可在界面检查或删除后再重试。服务未启动或端口不同会报连接错误，不要将其当作模型执行失败。

## 运行时观察什么

- 第一节点结束时，应只有规格文档；后端、前端和说明应由对应后续节点逐步产出。
- 每个节点有自己的会话，输入包含上一节点交接；后续 Agent 应读取当前目录中的规格和实现，而非重新设计整个应用。
- 所有节点使用同一个已选项目目录；模板保持未绑定状态，项目副本不影响原模板。
- 四个节点结束后才由你启动生成应用。节点报告应将未测试事项如实列出，不能把完成代码生成描述为测试通过。
- 如果节点失败或停止，下游应保持阻断。记录节点名称、界面状态、错误摘要和已生成文件，避免把失败轮次算成成功。

## 生成应用后的手动步骤

以下均由你执行，目前全部未执行。生成文件是预期交付物，本次准备不会预先写入业务代码。

在你所选的项目目录中启动：

```bash
python app.py --host 127.0.0.1 --port 8000 --db-file ./support.sqlite
```

打开 `http://127.0.0.1:8000`。若端口被占用，可自行改为其它空闲端口，并同步修改访问地址。

| 步骤 | 手动操作 | 预期观察 |
| --- | --- | --- |
| 1 | 首次打开空项目的页面 | 空列表有说明，全局总数及三种状态计数都是 0 |
| 2 | 创建“无法登录”，客户“青禾商贸”，描述“升级后账户登录失败”，优先级“高” | 新工单为“待处理”，总数 1、待处理 1；成功反馈可见 |
| 3 | 再创建“发票抬头调整”，客户“远山设计”，描述“需要修改发票抬头”，优先级“普通” | 两条工单，总数 2、待处理 2 |
| 4 | 搜索“青禾”，再组合选择“高”和“待处理” | 只显示“无法登录”，全局总数仍为 2 |
| 5 | 打开该工单详情，把状态改为“处理中” | 详情、列表与统计同步；待处理 1、处理中 1；当前“待处理”筛选下该工单移出 |
| 6 | 清空筛选，再把该工单改为“已解决” | 两条工单可见；待处理 1、处理中 0、已解决 1 |
| 7 | 搜索不存在的关键词，再清空 | 显示空结果；清空后恢复两条，不丢数据 |
| 8 | 尝试提交空白标题 | 页面阻止或返回清楚的错误，不新增工单，统计仍为 2 |
| 9 | 刷新页面 | 两条工单及状态保留 |
| 10 | 在启动终端按 Ctrl+C，再使用同一启动命令与数据库路径启动 | 两条工单、内容和状态均保留 |
| 11 | 将窗口调整至约 450px 宽 | 创建、筛选、详情、状态按钮都能访问，正文不被遮挡 |
