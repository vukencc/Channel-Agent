## 根因与修复

**交接与检索。** 旧检索账本按整个用户轮次和查询文本汇总。退款和无知识库答案事项可能共用查询，旧记录无法表达一条调用由哪个事项发起。现在调用方可填来源中的 `item_ref`，运行时只根据实际配对的调用与结果分别统计执行状态。未指定标识的调用单列；账本仍有 900 字符上限，超出时显示遗漏数。标识由模型填写，复核时仍需阅读查询及来源。已有模板和结构化、普通上下文两种模式都能收到新的来源核验提示。它要求引用前核对原文、区分客户表述和推断、将证据不足的项留待核实。专项用例在旧实现上先失败，随后覆盖同一查询跨事项使用、未关联、无效标识和预算截断。

**Windows 配置。** 原生基线为 7 failed、16 passed，涉及行尾、权限断言和创建文件符号链接。原渲染器在记录尾部固定写 LF，第二次同步可能再次替换文件。新实现从解析后的记录边界选择布局，保留值内的 CRLF。测试还发现以“全文是否含 CRLF”选择布局会被新增多行默认值误导，该输入已加入回归。POSIX 继续验证 `0600`。Windows 对新临时文件在创建时设置受保护的私有 DACL，刷新后原子替换，并对已合规文件验证重复同步不替换。Windows 原文件符号链接的夹具和拒绝断言保留。

**安装包。** 从修复前源码实际构建 Frontend wheel 后，独立解释器找不到 CLI、Web、Qt 共用的 `agent_frontend.runtime_loop`。可编辑安装直接读取源码，掩盖了遗漏。现在将模块列入 wheel 文件清单，并在 PR 的 Linux 工作流里从实际 wheel 导入并创建、关闭事件循环。
