# 本机 WebUI

WebUI 是本机单用户界面，复用现有会话、权限、工具与审计机制。它不依赖 CDN，也不需要 Node.js 或前端构建步骤；FastAPI 在应用启动和关闭时管理会话资源，见 [FastAPI 生命周期说明](https://fastapi.tiangolo.com/advanced/events/)。

## 安装与启动

在项目根目录执行：

```bash
uv sync --locked --extra web
uv run --no-sync ai-agent-web
```

服务默认监听 `127.0.0.1:8765`。在同一台机器的浏览器打开 `http://127.0.0.1:8765` 即可使用，无需访问令牌。`WEB_UI_HOST` 可设为 `localhost`、`127.0.0.1` 或 `::1`，`WEB_UI_PORT` 可设为 `1` 至 `65535`。配置项示例见仓库根目录 `.env.example`。

WebUI 仅接受本机 Host，并拒绝跨站来源；它不是局域网部署或远程访问产品，服务启动器只允许上述回环主机。每个可写 HTTP 请求还须带 `Content-Length`，请求体上限为 1 MiB。

## Agent Flow

左栏新建项目可选择 Agent 或 Flow，也可打开已有 Flow。画布支持节点拖动、端口连线、检查器中的连接按钮、删除、缩放和适配；Flow、节点及运行检查器提供项目、模型、权限、交接和节点会话入口。保存、运行与停止沿用 Core 的校验和执行规则。Web Flow 随 `web` extra 提供，无需额外开关；完整操作和交接边界见 [Agent Flow 指南](agent-flow.md)。

目录选择器浏览 Web 服务所在 Linux / WSL 的目录，不能把浏览器本机 Windows 目录句柄当作服务端项目；需要使用服务端可访问的 Linux 路径。

Flow API 使用 `GET/POST /api/flows`、`GET/PUT/DELETE /api/flows/{id}` 及 `POST /api/flows/{id}/run`、`POST /api/flows/{id}/cancel`；运行可带 `definition`，删除请求体须为 `{"confirm": true}`。状态 SSE 提供轻量流程摘要和 `flows_revision`，选中流程后再读取完整内容。这些接口沿用 WebUI 的来源检查与请求限制。

## 首条消息出现 URL 配置错误

如果发送首条消息时出现 URL 格式错误，检查 `BASE_URL`、`MODEL_FALLBACKS` 中的 `base_url`，以及仅在 `EMBEDDING_MODEL_SOURCE=API` 时使用的 `EMBEDDING_MODEL_URL`。WebUI 启动时会校验模型 URL、启用的 API 嵌入端点和代理环境；首次创建主模型或备用模型客户端时会再次校验模型 URL 和代理环境。模型 URL 或实际生效的代理变量中若有换行等控制字符，校验会失败且不会发出网络请求。代理按系统解析规则选择，同名小写变量优先于大写变量，即使小写变量为空也是如此；命中 `NO_PROXY`/`no_proxy` 的目标会绕过代理，其中独立的 `*` 表示所有目标都绕过。程序不会改写环境变量、自动清理 URL 或清除代理。请修正错误提示指出的变量，移除意外换行后重启实际运行的 WebUI 进程。

`.env` 不会覆盖进程已导出的环境变量，因此只修改 `.env` 可能无法修复配置；需同时检查启动该 WebUI 的 shell、服务管理器或容器环境。不要在问题报告中粘贴 API 密钥或完整 URL。

模型连接失败或流中断时，WebUI 会在会话中显示安全的中文连接错误和阶段保存提示；不会把底层异常正文写入用户可见错误。用户可发送后续消息继续已保存任务。首帧前的瞬时连接错误按 `MAX_RETRIES` 重试，首帧后不自动重放；详情见[模型连接诊断与恢复记录](model-connection-recovery.md)。


## 会话与工作区

界面支持创建、查看、切换、设置、删除会话，发送消息、停止运行、处理当前确认请求、查看任务、导出 Markdown/JSON，以及查看和明确确认后替换记忆。新建子 Agent 自动共享直接父 Agent 的项目工作区；每个根会话仍有自己的工作区。模型预设与权限模式和 CLI 使用相同会话设置。工具由框架管理，不再提供工具勾选项；HTTP 设置提交 `tool_names` 会被拒绝。具体文件共享和会话隔离边界见[会话工具说明](session-tools.md)。

Linux 上创建根会话时可填写已有项目的绝对目录，也可在“会话设置 → Linux 项目工作区”中浏览并选择系统上的项目目录，不必放在 `crud_tests`。留空或“恢复默认”使用原有会话目录。保存后立即切换文件预览与工具根目录，命令内统一映射为 `/workspace`；不会移动、复制或删除原有项目文件。目录选择随会话持久化，重启后继续使用，子 Agent 继承父目录。所有共享该项目的 Agent、工具及后台命令结束后才可切换；子 Agent 不能单独修改目录。系统目录、应用源码/凭据/状态/只读数据、符号链接及其重叠路径不能选择，目录被替换或消失时拒绝访问并提示重新选择。删除会话保留外部项目文件。

创建和会话设置也可选择命令环境：“隔离沙箱”或“Linux 本机”。该设置按会话保存，子 Agent 继承父会话环境；根会话所属项目空闲时才能切换。Linux 本机直接使用宿主工具、文件、网络与 localhost，不具备沙箱隔离保证，但仍使用当前权限策略、确认、审计、文件工具路径边界与命令 cwd 根身份校验。详见[沙箱说明](sandbox.md)。

工作区采用可拖动的三栏布局：左侧会话列表、中间对话、右侧任务和 Agent 状态；右栏可在上方查看任务分布与计划，下方查看运行监控和动态 Agent 阶段动画。底部状态栏显示当前 Agent 数、工作区、权限和模型。左右栏宽度及右栏上下分区可拖动调整，布局保存在浏览器本地；界面还会显示上下文用量、预算与压缩摘要状态。上下文处理细节见[结构化历史与上下文管理](context-management.md)。
输入框和底部状态栏可快速选择当前会话的模型与权限，选择后直接保存相应会话设置。权限选择器提供完全访问（`full_access`）、智能申请（`smart`）与只读（`readonly`）三个公开模式，默认智能申请；旧会话保存的 `standard`/`trusted` 保留严格确认行为，并映射显示为智能申请。Agent 忙碌时仍可编辑草稿，但草稿不会自动排队；当前任务完成后再发送。`Ctrl/Cmd+Shift+O` 打开新会话对话框，`Ctrl/Cmd+L` 聚焦消息输入框；`Ctrl/Cmd+K` 打开命令面板。输入框中 `Enter` 发送，`Shift+Enter` 换行。

设置 `DEBUG=true` 并重启 WebUI 后，工作区右上角会显示“运行调试”入口，可查看 Agent 层级、并发活动和模块调用。CLI 也有独立的终端调试面板；两种面板只显示各自进程的数据。总览保留 224 px Agent 轨道、两行 42 px 行为标签和短竖箭头；子 Agent 均可展开完整时间线。通信详情按需显示，局部详情在右侧独立滚动，窄屏使用抽屉；Agent 数量与共同时间尺度上的事件密度趋势可帮助浏览负载。事件密度不是 CPU 使用率或任务时长。配置与数据保留边界见 [Agent 运行调试](debug-runtime.md)。
调试页面的会话上下文入口可按需查看归档块及其原文，原文按页展示并在返回前隐藏已知模型密钥；打开普通运行追踪或导出快照不会包含摘要和原文。压缩不会删除完整历史归档。

“模型管理”可添加、编辑和删除本机保存的 OpenAI-compatible 模型连接，再在空闲会话的设置中选择。连接存于状态目录的 `.runtime-models.json`；POSIX 系统使用私有文件权限和原子替换。容量字段 `context_tokens` 与 `response_reserve_tokens` 是本地预算元数据，可编辑；应按实际服务或网关容量填写，留空时采用保守预算，系统不会按模型名称猜测窗口。运行时模型 ID 会写入会话，凭据不会写入会话记录、审计、导出或返回浏览器；编辑密钥留空会保留该连接原密钥，新建时留空表示不设置密钥，不会继承 `.env` 中的服务密钥。模型服务地址仅接受无用户名、密码、查询参数和片段的 HTTP(S) URL。环境配置的内置模型预设为只读。修改或删除模型前，所有引用该模型的会话与工具都必须空闲；删除前还需先把引用它的会话切换到其他模型。运行时模型选择只作用于主执行器，不会重配 `AUX_MODEL`、`CONTEXT_SUMMARY_BACKGROUND` 或 `MEMORY_AUTO_EXTRACT` 等环境配置路由；监督器仍由 `.env.supervisor` 独立配置。运行时模型请求使用所选连接自身的端点与凭据，不会套用全局 `MODEL_FALLBACKS`。容量和输入预算关系见[结构化历史与上下文管理](context-management.md)。此功能不新增环境配置项。

启用任务计划后，WebUI 的 `/plan` 看板通过只读 `GET /api/sessions/{identifier}/plan?cursor=&limit=32` 读取当前会话计划，展示步骤、依赖、就绪项、阻塞原因、完成自报与未验收状态。已有会话状态 SSE 包含轻量计划摘要；完整详情仍从 GET 分页读取。看板不启动任务或修改步骤，也不替代程序运行状态面板。状态语义、配置和限制见[任务计划使用说明](task-plans.md)。

## 清理缓存、日志与会话记录

工具栏的“清理数据”按钮或命令面板中的 `/cleanup` 会打开清理对话框，先预览缓存、日志的文件数和大小及会话记录数，再勾选范围并明确确认。缓存或日志的预览错误分别显示；其他类别仍可查看和勾选。Agent 或工具运行时不能清理。

项目内缓存只能位于 `PROJECT_ROOT/.cache/`；配置在项目外的专用 RAG 缓存也可清理，但不能与工作区、知识库原文、状态目录或显式本地模型目录重叠。缓存包含下载的模型，清理后下次检索可能需要重新下载，并会按需重置和加载运行时缓存。

日志清理涵盖 Agent 主审计、会话级审计与生命周期日志、`cli.log` 和已知命令日志，并保留本次清理审计记录。会话清理会把所有当前会话记录移入状态目录的 `.trash/`，包括结构化上下文归档；这只是将会话记录移入回收区，不等于彻底删除运行目录。工作区文件、知识库原文、共享记忆和导出文件保留。

文件面板只预览当前项目工作区 `SANDBOX_DIR/<根会话 ID>/`（默认 `crud_tests/<根会话 ID>/`），不提供写入。目录最多列出 500 项，文本内容最多显示 256 KiB 并标注截断；符号链接不跟随。安全打开依赖支持目录文件描述符和 `O_NOFOLLOW` 的平台能力，不支持的平台会拒绝文件预览。会话列表的并发监控实时显示 Agent、模型调用和工具状态，包括 `queued`、`waiting_workspace` 与 `running`。工具超时返回后，若后台只读操作仍在执行，它仍会占用真实工具并发额度并留在监控中，直到线程结束。

默认模型调用并发上限为 4、连续只读工具上限为 4、委派 Agent 上限为 2；RAG 推理并发默认 0，分别由 `MAX_CONCURRENT_AGENTS`、`TOOL_CONCURRENCY`、`AGENT_TASK_CONCURRENCY` 与 `RAG_INFERENCE_CONCURRENCY` 控制。RAG 并发为 0 时沿用只读工具池；设为正数时使用单独的 RAG 池。对同一项目工作区的串行工具操作会互斥，不同项目工作区及可并行只读工具可并行。共享工作区与会话独立数据的边界见[会话工具说明](session-tools.md)。

## 状态目录

WebUI 与 CLI 使用同一 `AGENT_STATE_DIR`（默认 `.agent`），状态目录持有单进程锁；CLI 和 WebUI 不能同时打开同一个状态目录。需要同时运行时，必须为其中一个进程提供不同的 `--state-dir`。使用新目录会建立一套独立状态，不会修改已有 `.agent` 数据。

```bash
uv run --no-sync ai-agent-web --help
```

入口还支持 `--host`、`--port` 和 `--state-dir`；主机仍须为回环地址，端口须在 `1..65535`。对应环境变量默认值见上文。
