# 原生 Agent Flow

Agent Flow 用有向画布组织 AgentCore 节点，让后续节点接收上游交接。当前可视化入口是[原生桌面 GUI](desktop.md)；CLI 和 WebUI 保留原有会话入口。

## 创建与编辑

1. 在桌面左栏点击“新建项目”，选择“Flow · 节点与交接”，填写名称并选择已有的 Linux 项目目录。也可稍后在 Flow 检查器填写项目目录和初始 Handoff。
2. 在左栏“Agent Flows”打开流程。点击或拖动“添加 AgentCore”，也可双击画布空白处添加节点。拖动节点调整位置，从节点右侧输出端口拖到另一节点左侧输入端口建立箭头。选中节点或连线后按 Delete 或 Backspace 删除；中键拖动画布，Ctrl 加滚轮缩放，“适配”显示整体。
3. 选中节点，在“节点”检查器填写名称、初始提示、项目目录、Handoff、项目内交接文件相对路径和模型。提示不能为空。项目和模型留空时继承流程设置；下游节点还继承上游项目。Flow 检查器可设置名称、项目、初始 Handoff、执行环境、权限模式和模型。
4. 点击“保存”持久化定义；标题星号表示未保存的草稿。点击“运行”也会携带当前草稿，由 Core 校验并保存后启动。运行期间不能编辑，按钮可用于停止；选中节点后可在“运行”检查器查看输入、输出、状态与错误，并打开对应会话。
5. 切换 Flow 或经典对话时，未保存的草稿仍保留在窗口中；退出时可选择保存、放弃或继续编辑。保存校验失败会留在窗口中，方便修正后重试。

## 执行与交接

流程必须至少有一个节点，不能形成环。每个根节点运行前必须指向已有项目；连接的下游节点使用同一项目，来自不同项目的上游不能汇合。Core 按依赖顺序执行，每个节点创建独立的真实 Core 会话。节点首次模型调用前，Core 读取指定的项目内相对交接文件（UTF-8，最大 256 KiB），并合并流程、节点和上游交接；路径读取校验项目身份且不跟随符号链接。提示要求 Agent 先阅读交接再处理项目。

仅当会话正常回到 idle、相关子任务、工具和后台命令均排空，且存在最终助手正文时，节点才成功。该正文标记为“Agent交接摘要，验证自报”并传给下游；摘要中的验证结论仍需自行核实。失败、检查点或取消会阻断尚未执行的节点。运行中，项目由同一管理器预约，允许当前节点及其后代使用，阻止其他会话抢占；这不承诺隔离独立状态目录进程或外部编辑器。

流程定义和最近一次运行状态保存在状态目录的 `flows/*.json`。重新打开应用可查看记录；进程中断后不会自动重放执行。删除流程记录不会删除项目文件或节点会话。
