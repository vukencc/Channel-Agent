# Agent Flow

Agent Flow 用有向画布组织 AgentCore 节点，让后续节点接收上游交接。可在[原生桌面 GUI](desktop.md)或[本机 WebUI](web-ui.md)创建和运行；两者共用 Core 的流程定义与执行语义。CLI 提供经典会话入口。

## 选择项目

“项目”指 Agent 实际读写的已有目录，不要求 Git 仓库或指定文件名。

- 在新建项目对话框、画布上方的“选择项目”或 Flow 检查器中点击选择按钮，打开可视化目录窗口。通过目录树、位置导航或路径栏定位 Linux / WSL 中的项目目录，确认后显示名称与完整路径；取消不会修改草稿。目录窗口用于选择已有目录，不创建或删除目录。
- 画布上方设置的是流程默认项目。起点节点可以在节点检查器选择独立项目；留空则使用流程默认项目。下游留空时继承上游项目，检查器会显示生效项目及来源。
- 两个起点可以处理不同项目，但它们不能汇合到同一个下游；沿连线不能切换项目。缺少项目、继承循环或不同项目冲突会给出提示，Core 在运行前继续校验实际目录、身份与访问边界。
- 路径仍可手动输入。选择器显示应用所在 Linux / WSL 文件系统；Windows 盘符路径需使用对应 Linux 挂载路径。运行期间不能更换项目。

## 桌面创建与编辑

1. 在桌面左栏点击“新建项目”，选择“Flow · 节点与交接”，填写名称并选择已有项目。也可先创建画布，再用画布上方的按钮选择项目。
2. 在左栏“Agent Flows”打开流程。点击或拖动“添加 AgentCore”，也可双击画布空白处添加节点。拖动节点调整位置，从节点右侧输出端口拖到另一节点左侧输入端口建立箭头。选中节点或连线后按 Delete 或 Backspace 删除；中键拖动画布，Ctrl 加滚轮缩放，“适配”显示整体。
3. 选中节点，在“节点指令”中描述该 Agent 的职责与要完成的任务；该项不能为空。节点项目和模型留空时继承相应默认值；下游项目优先沿连线继承。已有背景可在“可选补充背景”中添加。
4. 点击“保存”持久化定义；标题星号表示未保存的草稿。点击“运行”也会携带当前草稿，由 Core 校验并保存后启动。运行期间不能编辑，按钮可用于停止；选中节点后可在“运行”检查器查看输入交接、输出交接、状态与错误，并打开对应会话。
5. 切换 Flow 或经典对话时，未保存的草稿仍保留在窗口中；退出时可选择保存、放弃或继续编辑。保存校验失败会留在窗口中，方便修正后重试。

## Web 创建与编辑

1. 在左栏新建项目时选择 Flow，填写名称并选择项目；也可从左栏 Flow 列表打开已有流程。
2. 添加并拖动 AgentCore 节点，从输出端口拖到目标输入端口连线；也可在节点检查器选择目标并点击“添加连接”。选中节点或连线后可删除，使用缩放按钮和“适配”调整视图。
3. 在 Flow、节点和运行检查器中设置项目、节点指令、模型及可选背景，查看运行状态、输入和输出交接，并打开节点会话。Flow 可选择执行环境和权限模式。
4. 保存或运行当前草稿；运行期间可停止。切换页面内的 Flow 或会话时草稿保留，离开页面时有未保存提示；删除 Flow 需确认，项目文件与节点会话保留。

Web 的项目选择器浏览的是 **Web 服务进程所在的 Linux / WSL 文件系统**。浏览器本机的 Windows 目录句柄不是服务端项目；Windows 目录需以服务端可访问的 Linux 挂载路径选择。目录身份、授权和运行前校验由 Core 执行。

## Handoff 是什么，是否需要填写

Handoff 就是交接说明：让后续节点知道前一个节点完成了什么、还有哪些待办、有哪些验证结果或需要留意的问题。每个节点使用独立会话，项目文件本身不能完整表达这些过程信息，因此保留沿连线自动传递的交接。

例如“分析 → 实现 → 验证”：分析节点说明方案和待办，实现节点据此修改同一项目并交代改动与验证命令，验证节点再结合项目文件检查结果。节点结束时的最终助手正文会自动传给下游，用户不需要逐条复制，也不需要为了运行 Flow 手工创建 Handoff 文件。

手工 Handoff 只是补充已有项目背景，归入默认收起的“可选补充背景”：

- Flow 的“项目背景（可选）”提供所有节点共享的项目现状、约定或已有工作。
- 节点的“补充背景（可选）”只补充该节点需要了解的信息。
- “已有交接文件（可选）”读取项目内已有 UTF-8 文本，填写项目内相对路径，最大 256 KiB；不是必填项，也不限定文件名。文件在该节点首次模型调用前读取。

已有非空背景或文件配置会自动展开，原内容保持。要让节点做什么，应写在“节点指令”；背景说明提供执行时参考的上下文。留空所有手工背景仍会自动接收上游交接。

## 执行与交接边界

流程必须至少有一个节点，不能形成环。Core 按依赖顺序执行，每个节点创建独立的真实 Core 会话。首次模型调用前，Core 合并流程、节点、文件背景与上游交接；文件读取校验项目身份且不跟随符号链接，并提示 Agent 先阅读交接再处理项目。

仅当会话正常回到 idle、相关子任务、工具和后台命令均排空，且存在最终助手正文时，节点才成功。该正文标记为“Agent交接摘要，验证自报”并传给下游；摘要中的验证结论仍需自行核实。失败、检查点或取消会阻断尚未执行的节点。运行中，项目由同一管理器预约，允许当前节点及其后代使用，阻止其他会话抢占；这不承诺隔离独立状态目录进程或外部编辑器。

流程定义和最近一次运行状态保存在状态目录的 `flows/*.json`。重新打开应用可查看记录；进程中断后不会自动重放执行。删除流程记录不会删除项目文件或节点会话。本次界面简化保留原有持久化字段和已有交接，不要求迁移或重新填写。
