# Agent Flow

> 文档类型：当前使用指南 · [文档导航](README.md) · [快速上手](getting-started.md)

Agent Flow 用有向画布组织 AgentCore 节点，让后续节点接收上游交接。[原生桌面 GUI](desktop.md)和[本机 WebUI](web-ui.md)共用 Core 执行语义；CLI 提供经典会话入口。

## 模板与项目

左栏可独立创建 Flow 模板：编辑节点和连线，无需选择项目；模板本身不能在界面运行。新建 Flow 项目时可选择已有模板，导入为项目自己的独立 Flow 副本；修改副本或模板不会互相改写。也可先创建空白模板，再导入项目。项目可暂不选择目录，但运行前必须选择有效目录，不会回退到应用源码目录。

项目的目录及其设备、inode 身份是所有节点的工作区依据；运行前重新验证身份与访问边界。导入旧模板时会清空模板及节点上的旧工作区字段。项目的模型、执行环境和权限留空时继承模板设置；运行时保存生效设置快照，不反写模板或项目定义。

原生桌面和 Web 均可在左栏创建模板或项目。画布支持添加、拖动节点、端口连线、删除、缩放和适配；在节点指令中填写职责，保存后可运行项目流程并查看节点会话、输入和输出交接。运行期间不能编辑，可停止运行。切换时保留窗口内草稿，离开时提示未保存内容。

目录选择器浏览应用或 Web 服务所在的文件系统。Windows 原生应用可选择本地盘绝对目录，隔离命令会验证该目录到 WSL 的映射。Linux / WSL 服务使用 Linux 路径。选择器只选择已有目录，取消不会修改草稿。Windows 安装方式见 [Windows 指南](windows.md)。

Flow 和 Working 使用各自的工具栏，导航栏按钮及 Ctrl+B 仍可使用。Flow 的次要操作放在「更多」菜单；窄窗口工具栏分行显示。长名称和项目路径省略显示，悬停可查看完整内容。

在 Web 画布按住节点的输出端口拖动时，会显示随鼠标移动的临时连线；松到另一节点的输入端口才建立连接。松在节点正文或空白处不会连接，Escape 可以取消。画布随节点拖动扩展，正坐标原点保持稳定，节点不会被旧内容区域裁掉或在松手后回跳。

旧 Flow JSON 不会自动迁移或删除；可在界面将其作为模板显式导入项目。损坏的项目与 Flow 关联会隔离并告警，原文件保留。删除项目或模板不会删除真实项目文件或节点会话。

画布节点左键选择和拖动，右键打开节点检查器；Web 也可用 Enter、菜单键或 Shift+F10 打开。设计助手与检查器共用一个右侧区域，打开其中一个会收起另一个；均可关闭。悬停节点可查看任务、状态、模型、工具和子 Agent 概要。

## 设计、节点配置与便携模板

原生和 Web 的 Flow 入口提供可开关的右侧设计助手，没有现有 Flow 也可进入。选择模型和推理强度后，可多轮描述需求；设计请求不提供工具，模型须返回严格 JSON，模板通过校验后自动导入为新的未绑定模板，不覆盖旧 Flow、绑定项目或运行。两端优先保留上一版完整模板；模板本身超出后续对话容量时会提示未携带完整模板，较早对话也会按容量裁剪。全局默认模型不可用时，界面会选中可用的已保存模型；也可手动选择。隐藏设计助手保留草稿、对话及正在生成的请求；「停止」或「清空对话」会取消当前请求，迟到的结果不会导入。已提交的独立模板副本不会因随后关闭而撤销。

设计结果省略节点坐标或所有节点坐标完全相同时，Core 会按拓扑层级排列新图，避免节点重叠。已经明确指定且位置不同的设计保持原坐标；普通 JSON 导入仍保留文件中的布局。

节点可选模型、思考模式和推理强度：模型留空继承，思考模式可继承或选 `auto`、`enabled`、`disabled`，推理强度可继承或选 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`。设置用于实际模型请求；`disabled` 不发送 reasoning。服务商不支持所选参数时请求会报错。

模型连接的上下文容量在模型管理中声明，不根据模型名称猜测，也不自动继承其他连接的容量。未声明时按未知窗口使用保守输入预算（上限 16000 token）；大批量流程应先核对服务商容量，再填写经验证的数值。节点选择引用该连接，便携模板不包含连接的容量、端点或凭据。

节点工具默认继承部署目录（`tool_names: null`）；显式空数组只保留基础工具 `read_file` 和 `list_files`，基础工具锁定，其余可选，包括关闭 `run_command`。部署的 `MODEL_TOOL_NAMES` 和父级工具上限仍约束能力；基础工具与部署目录冲突时校验报错。经典 Agent 会话工具选择界面不变，权限策略、确认和沙箱仍生效。

### 节点自定义工具

设计助手可为节点生成 `custom_tools`，也可在桌面或 Web 节点设置的「动态工具定义（JSON 数组）」中手动编辑，并在工具选择中启用。设计和导入只校验定义，不执行代码；运行前应审查模型生成的代码及其读写、网络行为，模板中不要放凭据。便携 `version: 1` 模板可以携带定义，旧模板没有该字段时仍可导入。

例如，下面是节点设置中可直接粘贴的数组，工具接收文本并返回其字符数：

```json
[
  {
    "name": "count_text",
    "description": "统计文本字符数",
    "parameters": {
      "type": "object",
      "properties": {"text": {"type": "string"}},
      "required": ["text"],
      "additionalProperties": false
    },
    "code": "def main(arguments):\n    return {\"count\": len(arguments[\"text\"])}",
    "network": false
  }
]
```

每节点最多 16 个定义，名称不能重复或覆盖已注册工具。`parameters` 是根类型为 object 的受限 JSON Schema 2020-12：不支持引用、正则和组合 schema；最大 16 KiB、深度 12、128 个 schema 节点，每个对象最多 64 个属性。`code` 最多 32000 UTF-8 字节，须定义接受一个参数的同步 `main(arguments)`，返回可 JSON 序列化的结果；调用参数最多 64 KiB。`network` 默认为 `false`。

部署必须允许 `run_command` 才能使用自定义工具；节点可以隐藏通用 `run_command` 并单独启用自定义工具。实际调用经现有命令执行路径，遵循所选执行环境、权限、确认、审计、网络、超时和取消规则。`network: true` 不绕过部署网络策略；本地环境语义仍依所选模式，Windows 隔离命令经 WSL。子会话只能继承父会话允许的能力及完全相同的定义；复用节点会话时旧定义会被当前定义替换。

自定义工具可以完成实际 I/O，但代码和运行结果需自行核验。没有外部 API 时可写项目内 outbox 或人工处理队列，不能将其称为已向外部送达。

可导入[客服反馈动态工具模板](../src/agent_test/scripts/cases/customer_feedback_dynamic.template.json)，自行选择项目、模型并准备 `feedback.json` 与命名为 `support` 的知识库。它由真实设计助手生成工具，再经业务复核修订岗位提示，使用默认文本交接。读取、回复收件箱和人工队列都在所选项目内；完整实测及失败记录见[动态工具验证](agent-flow-dynamic-tools-validation-2026-11-11.md)。

上下文提示随节点实际工具变化：`history_search` 搜索归档摘要，`history_read` 按引用读取归档原文。关闭原文读取工具后，框架不会承诺仍能检索归档原文；获准的项目产物可用文件工具重读，已配置资料可用 RAG 检索，两者不代表任意旧对话可以恢复。归档策略、当前任务、完成操作收据及预算边界保持。

没有 `history_read` 时，最新尚未交付给下一次模型请求的完整工具调用与结果批次不会被预算整理移出窗口；旧版本已归档的尾批次也可由框架从会话记录恢复。如果固定成本与该批次仍装不下，会进入预算检查点，提示缩小读取量或核实模型容量，不扩大预算或让模型反复重读。有历史原文读取能力时保留既有硬预算归档路径。

画布可导出草稿，无需运行；原生和 Web 都可导入不超过 1 MiB 的 JSON 文件。格式为 `format: "agent-flow"`、`version: 1`，含标题、设置、节点和连线；保留节点 ID 和「复用会话」开关，剔除会话绑定、排队输入、运行身份、项目目录、历史、凭据及模型服务端点。相对 `handoff_file` 仅保存引用，不打包文件。导入建立未绑定的新模板；未知模型默认报错，只有明确选择缺失模型继承（API 为 `missing_models: "inherit"`）才将缺失引用改为继承。导入不会注册 RAG 数据源或项目，也不会降低权限策略。Web 请求体同样受 1 MiB 上限约束，JSON 包装可能使可导入文件实际更小。

更新代码后须重启现有应用进程；旧应用状态不会自动改写，已有四、五 Agent 模板保留。

此前工程用例中的 `schema_version` / `case_id` 配方不是这里的便携格式；已有应用内模板可先使用“导出”，再通过文件导入。文件只携带配置，不携带项目输入、RAG知识内容或模型安装包。本轮实现与验证边界见[创作功能验证记录](agent-flow-authoring-validation-2026-11-02.md)。

完整实际使用链路见[设计助手与客服Flow实测](agent-flow-designer-customer-validation-2026-11-03.md)。编辑较大业务文件时应选择 `edit_file`；`update_file` 保留单页以上文件不能全文覆盖的保护。长模板输出不完整时先精简共同规则和重复内容，设计助手会提示重试，不导入半份模板。

同一项目工作区的节点还可读取[工作区共享记忆](workspace-memory.md)，即使未复用节点会话；它是自报的参考摘要，不代替 Handoff 或业务验收。前节点的共享更新完成后才结束会话任务；写入失败或提交状态不确定会进入检查点并阻断下游。

## 复用节点会话

在 Web 或桌面画布中选择节点，在节点设置勾选「复用会话」并保存。默认关闭，每轮执行都会新建该节点的会话。启用后，首次运行建立会话绑定，同一项目的同一节点在原工作区内继续使用该会话。关闭后运行则使用新会话。应用重启后绑定仍有效；原会话已删除或其工作区曾被手动更换时，会新建会话。

运行前可以在「本次运行补充信息」中填写本轮输入，例如新收到的一批客服反馈。复用节点会把新信息和本轮上游交接作为一条新消息追加，会话历史继续受常规上下文预算约束。模型、权限及节点工具按当前流程设置生效。节点正常结束并排空相关工作后，只把本轮的最终助手正文交给下游。

含复用节点的项目 Flow 忙碌时，可输入新信息并点击「排队」。队列最多等待 16 轮，按提交顺序执行整轮流程，每轮内仍按连线顺序交接。运行失败、停止或应用重启后，待处理输入保留并暂停；再次点击「运行」从最早的一轮继续，若同时填写了新信息，它会加入队尾。中断的那一轮不会自动重跑。

## Working 运行视图

在桌面和 Web 左栏打开「Working」，可查看当前应用里正在排队启动、运行或停止中的 Flow 实例。节点按执行顺序展示。悬停节点可查看模型、状态、任务、工具和子 Agent 概要；左键选择，右键打开详情。Web 还支持聚焦节点后按 Enter、菜单键或 Shift+F10。详情显示运行阶段、任务、模型与推理设置、调用次数、交接验收和子 Agent 状态，可用「关闭」收起。

任务概要来自节点指令或实际委派文本的摘录。详情显示节点和子 Agent 的有效工具及描述，基础工具标注为锁定。模型在请求完成前显示配置值，有请求记录后显示最近一次记录的实际模型。子 Agent 统计按运行 ID 隔离，复用会话时不会混入上一轮，详情优先展示活跃子 Agent。看到「等待确认」时，可在对应会话处理操作确认。运行结束后，实例离开 Working，仍可在原 Flow 的运行详情查看结果。

## Handoff 与执行

Handoff 是沿连线自动传递的交接说明。每个节点有独立会话，正常结束后的最终助手正文传给下游，用户无需手工复制或创建交接文件。例如“分析 → 实现 → 验证”中，实现节点收到分析结果，验证节点再收到实现结果。

### 可选结构化交接

在 Web 或桌面画布选中节点，填写「结构化交接契约（可选）」并保存。留空时继续使用普通文本交接。下例要求输出工单编号、严重度和是否已执行操作三个字段。

```json
{
  "fields": {
    "case_id": {"type": "string"},
    "severity": {"type": "string", "enum": ["P1", "P2", "P3"]},
    "action_taken": {"type": "boolean", "enum": [false]}
  }
}
```

所有声明字段必填，禁止额外字段。支持 string、integer、number、boolean、object、array、null，对象和数组字段仅检查其外层类型。字符串、布尔值、空值和安全整数可限制枚举。小数需要精确枚举时可采用字符串字段。每个契约最多 32 个字段，字段名由字母、数字及下划线组成，首字符须为字母或下划线。

`fields` 是配置层，最终交接直接输出声明的业务字段，例如 `{"case_id":"CF-001","severity":"P1","action_taken":false}`。Core 在节点系统提示和本轮输入中明确列出顶层字段，并将约定转换成 JSON Schema 说明输出形状；新建或复用会话均按当前约定更新。框架不会替模型补字段或接受多余包装层。

启用后，当前轮要求模型给出单个 JSON 对象，允许完整代码围栏。前后夹带正文、重复键、字段或类型不符均会验收失败。运行详情显示「结构化格式校验」和失败原因。校验成功后，下游收到 JSON 及上游节点来源提示。交接仍是上游自报，业务结论、实际工具行为和项目文件权限分别核验。

格式失败时，本轮 Flow 标记失败，尚未执行的节点被阻断，等待队列暂停。可在失败节点的会话里查看原始回复。修正约定或节点指令后手动运行，框架会使用当前约定检查新一轮回复。导出的模板携带配置，运行时校验结果仅留在项目运行记录。

### 背景与执行顺序

需要自行体验完整场景时，可使用[四 Agent 售后工单手动用例](agent-flow-support-manual.md)：需求、后端、前端与交付说明依次工作，附完整配置和手动步骤。该用例只准备配置，不自动创建项目或运行；各节点也被要求将应用启动和功能测试留给用户。

所有节点按拓扑顺序串行调度；分支连线不表示并行或框架级条件路由。非编程场景见[客服反馈分流实测](agent-flow-customer-service-validation-2026-11-02.md)：分类后交给技术/服务分支，再由独立 Agent 模拟运维与人工。真实模型已跑完全部节点，但严格业务验收未通过；报告保留检索与人工边界等失败。

模板背景、项目背景、节点背景、可选交接文件和上游摘要按顺序合并。背景可留空；节点要执行的任务写在“节点指令”。交接文件是项目内已有的 UTF-8 文本，以相对路径填写，最大 256 KiB，首次模型调用前安全读取。

每轮执行消息会在交接背景之后明确当前节点名称、节点指令和本轮职责，提醒将后续任务留给下游；系统提示也会使用当前节点指令。这有助于模型区分项目总目标与当前阶段，实际遵循程度仍需验证，不能作为文件权限隔离保证。可复用的五节点业务用例与实测记录见[设备借用台验证](agent-flow-equipment-validation-2026-10-31.md)。

流程至少有一个节点且不能成环。只有会话正常回到 idle、相关子任务、工具和后台命令均排空，且存在最终助手正文时，才能验收节点。普通交接标记为“Agent交接摘要，验证自报”，配置结构化契约的节点还需通过格式校验。失败、检查点或取消阻断尚未执行的节点。运行中同一管理器预约项目，允许当前节点及其后代使用；不承诺隔离独立状态目录进程或外部编辑器。

连接中断、预算或计划等待导致检查点时，节点与 Flow 显示受控的具体停止原因；未知原因保留通用提示，不展示模型回复或服务商异常正文。修复不会将旧失败记录追认为成功，也不会自动重放失败节点。

所有节点结束后，应用先保存最终快照，再显示「已完成」。取消或失败时，应用在清理相关任务后一起更新运行终态和被阻断的下游节点。若清理未能完成，失败记录会说明项目预约仍保留。若最终保存失败，运行显示保存失败，待运行项暂停。恢复存储后，在同一应用进程点击「重试保存」，只写入已经执行完的结果。保存成功后，可用「运行」继续等待项。如果写入中途发生替换且应用无法确认新文件身份，需重新打开应用核对记录。重新打开后以能安全读取的磁盘记录为准，仍记录为运行中的一轮会标记为中断。

项目记录保存在状态目录 `projects/*.json`，模板和项目 Flow 定义及最近运行状态保存在 `flows/*.json`，项目副本通过 `project_id` 关联。重新打开应用可查看记录；进程中断后不会自动重放执行。Flow 的 local 命令写入边界及局限见[沙箱说明](sandbox.md)。
