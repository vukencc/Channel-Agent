# 长文件工具调用、内容截断与超时修复

## 实际故障

依据 `.agent` 最新会话 `1c9b3797…` 和 2026-09-27 18:01–18:03 日志：

- 初次生成的 HTML 为 **21,542 字符**，文件已成功创建。
- 细化任务调用 `read_file`，返回前 **20,000 字符**与截断提示，缺少续读入口。模型仍打算重建全文。
- 同一请求携带历史完整建文件参数与读取结果，输入增至 **50,299 字符**。
- 模型输出 442 字符说明后，在 **63.793 秒**触发 `ReadTimeout`，没有收到完整修改工具调用，所以原文件并未更新。
- 记录没有显示服务端 token 窗口溢出的 400 错误；本次确认的是工具内容截断、重复上下文与长输出断流。此前还有两次不相关的本地 RAG 检索。

这次没有继续延长 60 秒空闲 / 90 秒总时限，而是修复长文件工作方式。

## 改动与保护

| 环节 | 修复方法 | 保证与限制 |
|---|---|---|
| 文件读取 | `read_file` 增加字符 `offset`、`limit`、`search`，返回 `next_offset` / `EOF` | 默认每页 6,000 字符；可定位标签/函数，不再猜偏移；Unicode 和 CRLF 保持一致 |
| 文件修改 | 新增 `edit_file`，唯一原文精确替换 | 保留未选中内容，拒绝空锚点、歧义、未匹配和确认期间变化；写入仍需确认，使用临时文件与原子替换 |
| 截断覆盖 | `update_file` 仅允许不超过单页上限的小文件 | 大文件必须局部编辑，不能拿一页文本覆盖全文；新建文件与命令执行能力保留 |
| 上下文管理 | 新增 `core/context.py`，仅压缩发给模型的副本 | 省略较早的长写入参数/命令脚本；预算紧张时省略旧读取页，再按完整旧轮次淘汰；保留工具配对、最近操作与明确说明 |
| 内容上限 | 输入默认 64,000 字符、单次流输出默认 48,000 字符 | 字符不是 token；当前用户请求不静默裁剪；完整历史、工具参数和导出仍保存在磁盘 |
| 断流恢复 | 每轮至多一次带小步骤要求的恢复 | 不执行残缺 JSON、不重放已成功工具；第二次失败停止，保留已完成工作 |
| 会话预算 | 默认 24 次交互，逐次告知剩余次数 | 用尽后保存为 `checkpoint`，CLI 显示“阶段保存·可继续”，不再抛轮数异常，也不宣称整个任务完成 |
| 旧会话 | 请求时附加最新工具协议 | 不改写用户保存的系统提示词；旧会话无需重建即可使用新工具与分页 |
| UI 响应 | 上下文准备放到工作线程 | 长历史复制、压缩不直接阻塞输入事件循环 |

只有 API 请求中的工作副本会省略内容；`.agent` 中的完整记录、分页浏览与导出没有因此被删减。长文件细化仍可能需要多轮交互，输出内容越多，总生成时间仍会增加。

## 实验与发现

使用最新真实会话的历史、原 HTML 副本和原始“大幅细化”要求，在独立临时工作区自动确认测试操作。原会话及原文件不修改。未换成短文件或固定回答来制造通过结果。

| 实验阶段 | 结果 | 后续处理 |
|---|---|---|
| 用户原始实验 | 读取截断，输入 50,299 字符，63.793 秒模型断流，无修改落盘 | 增加分页、局部编辑与上下文压缩 |
| 第一版重放 | 12 次模型请求均未超时，已生成 16,822 字符新文件，但在 90.853 秒触发旧轮数上限 | 增加文本定位、24 轮预算及预算提示 |
| 第二版重放 | 长命令脚本未压缩，生成 45,481 字符文件后达到工作上下文上限 | 将长 Shell 脚本纳入压缩 |
| 完整压缩后第 1 轮 | 24 次请求无超时/上下文超限，最大输入 42,373 字符，单请求最长 15.313 秒；总计 192.215 秒 | 仍因预算耗尽异常结束，不计为完整任务成功 |
| 完整压缩后第 2 轮 | 24 次请求无超时/上下文超限，原文件副本改为 32,653 字符；单请求最长 23.412 秒，总计 210.067 秒 | 同样触及预算，增加阶段保存/继续状态 |

一次模型误用 `create_file` 创建已存在文件被正确拒绝，随后自行改用新文件/局部编辑；这属于保留的真实工具反馈，不能宣称模型永不选错工具。两轮共 48 次请求无流超时，但都没有自动完成全部艺术细化要求。

调试中另有两次进行中的尝试，在确认同一缺陷后主动停止，以免继续消耗 API；未作为成功样本。

**最终状态复验：** 同一原任务运行 199.148 秒，完成 24 次模型请求和 27 次工具执行，模型请求全部正常结束，最长单次 18.644 秒；无流超时和上下文超限。原始工作历史达到 145,561 字符时，发送副本为 61,336 字符，没有移除旧轮次。新增 `cycling.html`（9,670 字符）及配套资源落盘，原 HTML 副本保持不变。最终状态为 `checkpoint`、错误字段为空，明确提示阶段保存、整个任务尚未确认完成。阶段继续/重启恢复由回归测试验证；没有把 checkpoint 计为艺术任务完成。

## 使用与交付范围

重启 CLI，在原会话发送“继续”即可使用新工具协议。遇到“阶段保存·可继续”，已执行的修改在实际工作区中，不会回滚；可查看文件后继续下一阶段。
